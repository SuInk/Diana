# SOUL.md

每台机器人的人设就是一份 Markdown：她是谁、在乎什么、怎么说话、长什么样。整份原样放在系统提示词的最前面，外面不加任何包装。

以前人设散在六七个地方：正文、品格层（`soul`）、自称、句尾语气词、动作描写开关、填空题 / 接管两种模式，运行时再把它们各拼一段进提示词。几处互相打架时，模型只能挑一边听，而用户在界面上改了开关也看不出为什么没效果。现在只剩这一份。

## 怎么写

这是 Diana 自己的写法：

- **讲理由，不列规则。** 规则总会漏掉没料到的情况；讲清楚为什么，没写到的场合她也能自己推出该怎么做。只有做错了代价很大的少数几件事才写成硬线，而且数量要少。
- **写一个人，不写一张清单。** 以段落为主，列点只用来强调。读完的人应该能预测她碰到没见过的话题会怎么反应。
- **用「我们」的口吻写她。** 写文件的是主人，称呼她的名字或「她」，不写成「你要……」的命令句。
- **身份要稳。** 语气可以随场合变，核心身份不变。写明别人起外号、逼她演另一个人、坚持「你真正的样子其实是……」时，她可以接玩笑，但不会因此变成另一个人。性格是她自己的，不是一套戏服。
- **老实，不讨好。** 说话可以有分寸，但不为了有分寸牺牲诚实。

推荐的结构（标题只是给人看的，运行时不解析）：

```markdown
# 名字
## 基本情况       名字、性别、社会情况（年龄、职业或身份、和主人的关系）
## 概述           这是谁，我们希望她成为什么样的存在
## 核心价值       不越界、正派、守主人的规矩、真的有用；整体权衡，不是机械排序
## 真的有用       什么叫真的帮上忙，为什么不等于讨好、不等于越长越好
## 正派           诚实具体指什么；别人的评价不是事实；少数几条硬线
## 守规矩，也可以被纠正
## <名字>的本性   性格从哪来；身份为什么不变；怎么说话；长什么样（可不写，默认照自己的头像）；怎么对待错误
## 结语           没想清楚的地方，这份文件还会改
```

不用写的东西：输出格式和分条、工具和能力、时间和发言者、在哪个群或哪个平台。这些运行时会按当轮情况另外注入，写进来反而两边打架；写死「你在这个群里」，同一份人设被私聊用到时就是假话。

示例对话可以不写。模型会把示例照抄成模板，而口吻一旦对了，聊天记录里她自己最近的回复就是最好的示例。

长度：界面上超过 2500 字给提醒，4000 字是人设库的上限。写得越长，模型越抓不住重点。

内置的六份（`model/assistant/souls/*.md`）都照这个写法，可以当范本。

## 放在哪、谁能改

| 位置 | 说明 |
| --- | --- |
| 机器人配置 `system_prompt` | 这台机器人的 SOUL.md。JSON 键名沿用 `system_prompt`，存量配置不用迁移。留空时用内置的默认人设。 |
| 群配置 `system_prompt` | 非空时整份替换机器人的，只在这个群生效；留空跟着机器人走。 |
| 人设库 | 几份具名的 SOUL.md，是套用来源，不是活绑定：点一份就把正文填进编辑框，保存配置才生效；库里那份之后再改，不影响已经保存的机器人。 |

只有人能改 SOUL.md。机器人自己写的是[自述](self-notes.md)，进请求尾部的另一层，改不动 SOUL.md。

## 人设库

- **内置人设**编译在程序里（Diana、真人感、猫娘、助手、女友、男友），列表里排最前面，只读。想改就套用后另存一份自己的。
- **导入**：`.md` 是一份 SOUL.md，名字取第一行一级标题，没有标题用文件名。旧版 `.json` / `.yaml` 人设文件不再导入。SillyTavern 角色卡（JSON 或内嵌卡的 PNG）也收，卡里的字段拼成正文，内嵌世界书并进世界书。
- **导出**：每一份都能导出成 `名字.md`。
- 导入只增不减：同名但内容不同的改名为「名字 (2)」，同名且正文一样的跳过。

## 旧口吻

聊天记录里机器人自己以前的回复，以 assistant 身份原样回放。模型模仿这些回复的力度，远大于模仿开头那份 SOUL.md。换过一次人设，旧口吻就会借着历史一轮轮延续下去：一台机器人换掉猫娘人设两周后，仍有六成回复带「喵」。

所以尾部的语气锚点（离生成最近的那段）明说：「聊天记录里你自己以前的回复可能是旧的口吻，照 SOUL.md 说话，不照着以前的回复学。」

## 从旧版升级

读到旧配置、人设库里的旧条目时，旧字段渲染成原来运行时注入的那几段文字，并进 SOUL.md，然后清掉。同一份旧配置升级前后模型读到的指令一致，只是从「运行时拼」变成了「写在正文里」，在编辑框里看得见、改得了。

| 旧字段 | 去向 |
| --- | --- |
| `soul`（品格层） | 渲染成原来的「【你的品格】……」一段，放在正文最前面 |
| `self_reference` / `sentence_enders` | 渲染成原来的「自称偏好 / 句尾语气词偏好」一段，放在正文后面。自称只填了「我」、又没有语气词时不写 |
| `action_description_enabled: true` | 渲染成原来的动作描写说明，放在正文后面 |
| `persona_mode` | 直接丢弃。原来运行时注入的回复规则（聊天还是求助、节奏、答多长、不用表情符号等）现在对所有人设都注入 |
| `reply_style` | 和以前一样，一次性并进正文 |
| `persona_id`（人设库绑定）/ `custom_persona` | 丢弃。人设库回到套用来源，库里改了不再同步到机器人和群 |
| 人设库条目里的 `prompts` / `extra_criteria` / `account_safety_rules` / `persona_version` | 丢弃。提示词覆盖和判据是机器人自己的设置，机器人配置里的原样保留 |
| 人设库条目和机器人配置里的 `daypart_tone_enabled` / `persona_mode` | 丢弃。「语气跟随时段」整个去掉了：深夜困、清早迷糊这类作息表演会引着她按服务器时钟催人睡觉，要这种性格就写进 SOUL.md |

两个边界：

- **接管模式的旧配置**：原来接管模式下运行时不注入那几段回复规则，现在会注入。正文里如果自己写过同样的规则，会说两遍，删掉正文里那段即可。
- **分群的旧表达覆盖**：群自己写了人设正文时，群级的自称、语气词、动作描写并进群的 SOUL.md；群没写正文、只改了这几项时，这几项丢弃，不会为了保留它们把机器人的 SOUL.md 抄一份进群配置——那样这个群以后就跟机器人的人设脱钩了。
