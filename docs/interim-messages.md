# 一轮里中途说一句（send）

内置 Agent 在一轮回复里可以发好几次消息：先说「我去查一下」，接着调用工具去查，查完再发结果；长任务每做完一个阶段报一句进度。发一条不代表这一轮结束。

## 为什么

以前一轮只在收尾那一下发话，工具调用旁边的文字不会发出去。模型要么闷头跑完十几步才开口，群里看着像没反应；要么先回一句「我去查」就收工——这句发出去，这一轮也结束了，承诺的「查」从没发生。

## 怎么用

模型说话只有一个工具 `send`（原来的 `say` 和 `agent_finalize` 合并而来）。它怎么算取决于同一步里还调了什么：

- **只调 `send`**：这几条就是本轮的回复，本轮结束。填 `silent=true`、`text` 留空就是这一轮不说话，`silent_reason` 写一句原因（只进日志）；只留空 `text` 没填 `silent` 的也按不说话处理。本轮最后一步必须是 `send`。
- **`send` 和其他工具同一步调用**：这句是中途发言，工具照常执行，本轮继续（`agent.Config.Interim`）。同一步只有检索（`web_search`、`browser_render`、`tool_search`）时立刻发出，赶在慢检索之前；带别的工具时先执行工具，成功了才发，失败了这句不发，模型会收到「这句没有发出」——不然「定好了」先发出去，提醒却没建成。
- 照老历史发来的原生 `agent_finalize`、`say` 调用按 `send` 处理，老收尾的 `silent=true` 照样是不说话。
- 中途发言一轮最多 3 次，每次一句不超过 80 字的话，不能换行或分条。它不是用来把答案拆开发的，答案本身最后单独 `send`。
- 说了「去做」就必须接着调用工具真的去做，不能说完就收工。
- 发出去的话对方已经看到了，最后只 `send` 还没说过的内容；都说完了就 `send silent=true`。

2026-10-27 用 gpt-6.1-sol 回放 36 条生产首步：「纯文本即结束、只有静默才调收尾工具」让静默从 3 翻到 6；合成一个 `send`、空正文即静默后，静默 2 对 1，工具调用 11 对 14，36 条全部走 `send`。

合并时一并删掉了 `silent`/`silent_reason`，上线后模型自选静默从 0.9% 涨到 8%～10%，几乎全是主动接话。10-28 把 `silent` 和理由加回 `send`，同时续接历史把上一轮的回复记成普通发言（见 [group-prompt-cache.md](group-prompt-cache.md)）：用 gpt-6.1-terra 回放同一批线上首步，原本静默的样本从 16～19/21 降到 9/23，原本正常回复的 24 条没有一条转成静默。

## 收尾时的规则

- 中途说过话以后，这一轮不再被合并重来（`sealDirectReply`），否则重新生成会把那句再说一遍。
- 收尾没有新内容时不再补「我这边没有生成有效回复」；收尾正文和中途某一句一模一样时不发第二次。
- 中途的话走和最终回复同一个出口（`sendOutgoing`），照样记进聊天历史、去句号；发完重新点亮「正在输入」。
- 中途的话不过发送前审核：审核要多等一次模型，「我去查一下」这种短话用不着，靠长度和次数上限兜着。只有第一条最终回复会引用和 @ 对方，中途的话不引用。

代码在 `model/assistant/interim_message_tool.go`，Agent 那一侧的规则在 `model/agent/runner.go`。
