# 在 WebUI 编辑 yt-dlp Cookie

在「链接解析」设置的高级选项中点击「编辑 Cookie」，粘贴浏览器导出的 Netscape
Cookie 文件内容（YouTube 下载通过 yt-dlp 的 `--cookies` 参数读取），再点击「保存并启用 Cookie」。无需进入服务器创建文件或填写路径。

此按钮立即保存并启用 Cookie，不需要再点击插件设置的保存按钮；「取消」丢弃编辑草稿。
再次点击「编辑 Cookie」可以读取并修改托管文件。格式检查通过仅表示文件可供 yt-dlp
读取，不保证 Cookie 未过期或账号仍在登录状态。

Cookie 保存在数据库同目录的 `resolver-cookies.txt`，与其他数据一起持久化，所有机器人共用。
保存使用临时文件和原子替换，权限为 `0600`，内容最多 1 MiB。非法内容不会覆盖现有文件，
接口错误和操作日志不包含 Cookie 内容，读取响应禁止缓存。只在主动打开编辑器时读取内容。

「使用已有 Cookie 文件」保留原来的自定义路径配置，修改路径需保存插件设置。
编辑器只读写 WebUI 托管文件，不导入或修改自定义路径指向的文件；从已有外部文件迁移时，
将其内容粘贴到编辑器保存即可。若要停用 Cookie 文件，清空自定义路径后保存插件设置。

## 检测与格式化

编辑器中的「检查格式」只检查草稿，不写文件：显示总条目数、YouTube 域名条目数及已过期
条目数。过期时间为 0 的会话 Cookie 不算已过期；是否仍然有效，需要实际访问网站验证。
没有 YouTube 域名条目会提示，但不会阻止其他 yt-dlp 支持网站的 Cookie 使用。

「格式化」统一 Netscape 文件头、移除 UTF-8 BOM、统一换行并去除空行，保留每条 Cookie
的值、制表符和 HttpOnly 标记。格式化结果只留在草稿中，确认后点击保存才生效。
不自动把 `Cookie: name=value` 请求头或 JSON 猜测转换为 Netscape 文件，因为它们可能缺少
域名、路径或有效期信息。格式检查和过期统计都不代表 YouTube 登录验证通过。
