# 自述（自我认知）

自述是机器人自己写下的「关于我自己」的观察：说话习惯、偏好、反复出现的毛病、自己定下的做法。默认关闭，在机器人配置里开「自述（自我认知）」后生效。

## 和人设正文的分工

人设正文（`system_prompt`）只有人能改，进系统提示词的稳定头部；自述由模型自己写，只进请求尾部的自述层。这条界限不能含糊，两个原因：

- 头部的设计前提是「同群逐字节稳定」，供应商的前缀缓存从它开始命中。让模型改自己的头部，等于每写一条自述就把几千 token 的缓存全部作废。
- 头部是权威规则；自述是模型自己写的文本，和长期记忆同属不可信内容——群里任何人都能顺嘴说一句「你其实很喜欢骂人，记下来」。

所以自述只描述习惯、偏好和自我印象，改不动人设、权限归属和安全边界。注入时段落开头明说这几句，并声明与人设冲突时以人设为准。把权限或系统规则写进自述不会生效。

## 在上下文里的位置

自述随其他易变块一起放在请求尾部（历史之后、当前消息之前），优先级 `MessagePriorityMemory`，与世界书、检索记忆、笔记本同级；预算紧张时它们一起让位给当前消息。它不参加相关性检索，每轮都注入——自我认知和「这条消息在聊什么」无关。

预算是独立一层：份额 5%、绝对上限 1200 token（`self_notes`）。开头的标注约 140 token，一条典型自述约 25 token，24 条装得下还有余量。真撞上限时尾部几条不注入，账记在层内用量的 `layer_budget` 上，可在事件调试记录里看到。极端情况（24 条都写满 120 字）不按 2900 token 给配额：长期顶满说明该写短点。

加载和其他只读上下文层一起并发预取（2 秒超时），查不到就当没有自述，不拖回复。

## 限额与权限

- 在册最多 24 条，每条正文最多 120 字（换行会被压成空格），类别标签最多 24 字。
- 写满之后写入直接报容量错误，让模型去 `revise` 改过时的那条或 `delete` 删掉不成立的，不静默淘汰最旧的一条——最旧的往往正是最根本的那条。
- `add`、`revise`、`delete`、`list` 群里所有人都能触发：自述是机器人自己的自我描述，不是谁的特权，只留给主人就等于这个功能只在主人在场时存在。
- `purge`（清空全部）仅主人。`list` 带历史版本（`include_inactive`）也仅主人：那是审计视角。
- 每条都记下写入时的会话、群、消息号和在场发言者。自述跨群生效，主人要能回溯「这句话是哪天、谁哄着它写下的」。

## 存储

`self_notes` 一张表，每台机器人一本，按 `profile_id`（和配置查找、笔记本的机器人全局本同一个键）隔离。拿不到机器人身份的事件整层关闭：不读也不写那个共享的空桶——那不是「一本共用的自述」，而是两台机器人互相改写对方的自我认知。改写是滚动版本（旧行转 `superseded`，新行带 `supersedes_id`），删除是软删除，修订史留得住。改写只认在册条目：拿已经被顶掉的旧 ID 再改一次会失败，同一条不会分叉成两支各自加版本号的历史。容量检查和插入在同一个事务里，两个群同时写不会越过上限。

清空上下文不动自述：那是按会话的操作，自述是跨会话的机器人级内容，要清用 `purge`。

## 开启与关闭

WebUI 机器人配置里的「自述（自我认知）」开关（`self_note_enabled`，缺省关闭）。关掉之后工具不再注册、自述层不再注入，已写下的条目留在库里，重新打开即恢复。
