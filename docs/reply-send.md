# 一轮只说一次（send）

内置 Agent 的主回复只在做完以后说一次：要查、要做的先调用工具，看过结果再 `send`。一轮里没有「先说一句、接着做」的中途发言。

## 怎么用

- 模型说话只有一个工具 `send`（原来的 `say` 和 `agent_finalize` 合并而来）。一步里只调 `send` 就是本轮的回复，本轮结束；一步里调几次 `send` 各成一条消息。
- 填 `silent=true`、`text` 留空就是这一轮不说话，`silent_reason` 写一句原因（只进日志）；只留空 `text` 没填 `silent` 的先退回一次，再空也按不说话处理。
- `send` 和其他工具同一步调用时不发：工具照常执行，模型收到「这次 send 没有发出：同一步还有其他工具。看过结果后再 send。」
- 工具调用旁边写的正文不会发出，要说的话都写进 `send`。
- 照老历史发来的原生 `agent_finalize`、`say` 调用按 `send` 处理，老收尾的 `silent=true` 照样是不说话。

## 收尾与单次调用

- 模型只调 `send` 时直接作为本轮终结步骤收尾，不再额外发起一次全量草稿「说了却没做」复核（先前每次纯聊天收尾都要多花一次主模型调用，线上 81.8% 返回空结果、仅 2.7% 命中且存在误打回，徒增中位约 3 秒、均值 5 秒以上的回复延迟）。
- 模型写纯文本时照旧先退回一次「只有 send 会发」（`agent.Config.PlainTextNotSent`）；第二次还是纯文本就当作 `send` 直接收尾。
- 仅当本轮实际调用过联网检索/网页读取时，才会运行联网细节复核（`agent.Config.ResearchDetailReview`，见 `model/agent/research_review.go`），纯聊天零额外模型调用。

## 为什么

- **中途发言大多不是中途**：11-18～20 线上 1239 步只调 `send` 填了 `continue=true`，下一步真去调工具的只有 100 步。其余是把整条回复当中途发言发出去，再续出一步：435 步又说一句，95 步又发一条最终回复，346 步改成不说话，255 步撞上续步上限。群里看着一会儿一句，多出来的步骤约占回复输入 token 的三成。
- **改成必填的 `mode`（final/continue）没用**：swe-2 回放 15 条，continue 误用从 9 条降到 0，但静默从 1 涨到 5，该查、该改图的样本也不做事直接收了尾。
- **去掉全量收尾复核**：11-26～28 线上 839 次收尾复核中，686 次（81.8%）输出空 JSON、仅 23 次（2.7%）命中且包含正常玩笑/如实说没看过的误打回；每次额外增加约 3～5.8 秒主模型往返，直接移除后纯聊天回到单次主模型调用。

代码在 `model/agent/runner.go`（收尾）、`model/agent/finalize.go`（`send` 定义）、`model/agent/research_review.go`（联网细节复核）。
