# 图片发送与重试

保留现有 HTTP 分享链接发送方式。发送前为 Diana 登记的本地媒体建立使用引用，每次重试前将同一个链接续期到至少十分钟以后，来源和发送去重身份不变。

发送期间，定时清理只标记待清理，不删除正在使用的文件。发送成功、最终失败或取消后释放引用，最后一个引用释放时执行待清理操作。图片、视频、音频和文件的本地分享链接适用；外部链接不被改写。引用仅在本进程内有效，重启后的恢复仍要求分享记录和原文件存在。

群发送退避分为普通文字与媒体两个通道。图片、音频、视频、文件及合并转发的失败等待不会占用文字通道；同一通道仍保持串行重试。等待通道锁支持请求取消，避免已经超时的消息继续卡在锁上。平台确认的退群、禁言等群级不可用状态仍按原规则处理。

启用了群联调的控制台，可向 `POST /api/assistant/group-test` 传 `one_shot: true`，进行一次最长 30 秒的真实发送，不进入群发送退避队列。仍要求控制台认证与群联调开关，默认行为不变。必须以平台返回的消息 ID 验证成功。

不将图片改成 base64。该修复不保证平台上传或网络永不失败，也不能恢复已经被清除的分享记录；历史链接失效后需用保留的原图重新分享。

## 跨会话文件转发

原生转发失败后，文件有独立下载 URL 或本地来源时，重发会清掉源消息的 `file_id`、`fileId`、`id`，让接入端重新上传到目标会话，避免优先复用源群文件 ID 而没有实际上传。原消息的元数据不变；只有平台 ID、没有独立来源的同平台附件保持原行为，不保证这种引用可以跨群复用。

用户说“继续”时，即使文件消息没有独立入库，也可以从当前会话的内存历史引用中恢复；内存没有时，最多查询当前会话最近 200 条持久化消息的引用。不搜索其他会话，也不接受明确属于其他群的引用。超过这个窗口或下载链接失效时，仍需重新引用或提供文件。

经运行时核验的机器人主人不受“来源会话 10 分钟 5 次”总量限制，便于按要求发往多个目标；同一来源向同一目标的 15 秒冷却仍生效。普通成员保留原有总量限制，主人发送不占用普通成员额度。目标准入、屏蔽、平台自身的频率限制不变。成功结果允许模型继续处理尚未发送的目标，但不应重复发送已经处理的目标。

验证：2026-11-01 在 miku 使用生产原文件参数及 SnowLuma v1.14.10 的解析和发送函数做隔离回放，旧参数走发布源 ID，修正后走 URL 上传；底层网络调用替换为记录器，未向群发送消息。模型回放使用 `gpt-6.1-terra`：首次发送后的成功结果改用新提示后，模型继续处理下一群；“继续”场景将原文件查找失败替换为模拟的成功重发结果后，模型仍使用原文件 ID 发往下一群，没有改转用户指令。模型返回的发送调用未执行；确定性回归覆盖附件重发、历史引用恢复与跨会话隔离、主人多目标发送和普通成员限流。
