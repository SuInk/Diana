# WebUI 管理对话

用 WebUI 管理员账户登录后，从侧边栏打开「管理对话」（`/admin-chat`）。可以直接要求安装 Skills、配置 MCP，或者结合 Diana 的配置、错误日志、消息处理事件和主机资源排查故障。使用已有的对话模型和内置 Agent；不要求机器人已经连接平台，也不需要向群里发送测试消息。

在输入框底部的机器人选择器中选择机器人，可按名称、平台或 ID 搜索。此选择独立于侧边栏的全局作用域。对话历史按 WebUI 登录会话、机器人与会话 ID 隔离，切换回来会恢复各自的记录；任务执行期间需先停止再切换。选择「全部机器人」时，诊断和群聊记录可查询全部机器人；Agent 执行使用默认配置和默认对话模型。选定机器人后使用其模型分配、安全/标准模式、命令白名单、沙盒、网络和文件写入设置。安全模式不启动第三方进程，不提供脚本或 MCP 执行和安装变更；Skill 说明及资源仍可读取。

页面参考 Codex 的轻量对话布局：窄侧栏只显示会话标题，聊天区显示消息，底部保留一个输入框。去掉重复页头、卡片外框、消息头像和常驻工具栏，跟随 WebUI 的浅色、深色与强调色设置。点击右上角新建图标按问题新建多个管理会话；标题来自首次提问，清空当前会话后重新生成。列表的搜索图标可搜索标题与最近消息；会话列表可收起，窄屏展开时完整显示列表，选中会话或点击返回图标回到聊天区。

机器人选择放在输入框底部。「＋」提供群聊搜索与安装入口；群聊搜索弹窗可填写群号、关键词和时间范围，提交后由管理助手执行查询。右上角「更多」提供运行诊断、Skills/MCP 检查、载入上一条、执行权限和清空会话。快捷提示会填入输入框，检查后再发送。输入框支持 Enter 发送、Shift+Enter 换行，中文输入法选字不会触发发送；执行时发送按钮切换为停止。

助手回复使用简洁文本排版，保留复制回复和折叠的实际工具执行记录；消息时间在悬停或键盘聚焦时显示，窄屏始终显示。翻阅较早记录时，新消息不会强制滚动到底部，可点击「回到最新消息」。弹窗支持 Esc 关闭和键盘焦点循环，关闭后回到打开入口。管理对话只展示已有功能的真实结果。

## 使用示例

- 「检查当前运行状态和最近的错误，找出机器人没有回复的原因。」
- 「列出已安装的 Skills 和 MCP，测试 github 服务的连接。」
- 「安装 `https://github.com/Wei-Shaw/sub2api/tree/main/skills/sub2api-admin`，保留脚本和参考文档。」
- 「配置一个远程 MCP，地址是……，然后验证连接。」
- 「搜索群 123456 最近 7 天提到 MCP 的消息，列出发送者、消息编号和时间。」
- 「查 2026 年 10 月 2 日这个机器人的全部群聊，看看谁反馈过连接失败。」
- 「按时间顺序读取群 123456 今天的记录，分批继续查询后总结。」

安装、卸载与 MCP 变更使用原有的确认码机制：助手先说明完整变更与来源，管理员回复本次确认码后才执行。安装文件和 MCP 配置进入 Diana 现有的全局扩展目录，与「扩展」页面共用。带资源的 Skill 应通过仓库 zip 和 `subdir` 安装，单独的 `SKILL.md` 不包含其脚本。

## 群聊记录搜索

`admin_group_history` 只读查询本地数据库中的群消息与已保存的机器人回复，按机器人身份隔离，同群号不会混入另一台机器人的记录。群号为空时跨所选机器人的群搜索；关键词为空时读取最近消息。关键词按连续文本匹配，可匹配正文、已有图片描述、发送者名称/ID 和消息编号。

默认查询最近 24 小时、最新消息在前。可指定起止日期、服务器本地时间或带时区的 RFC3339 时间；只有结束日期时包含当日最后一秒。结果给出实际查询窗口、服务器时区、机器人来源、群号、消息编号、发送者与时间。每页最多 50 条，可通过 `next_offset` 续查，续页应复用返回的起止时间；长消息与单次输出会明确标记截断。关键词只存在于截断部分时，可缩小时间范围或减小每页条数再查。

单次正文与图片描述合计最多 16,000 字，每个字段最多 12,000 字，并随每页条数分配预算。减少每页条数可读取更多原文，超过字段上限的内容仍会明确标记截断。

此功能搜索 Diana 已接收、持久化且尚未清理的记录，不会向平台拉取完整历史。私聊和通知事件不在结果中；来源不明的旧群消息仅在「全部机器人」中显示。查不到不能证明群里从未发过该消息。消息处理事件仍由诊断工具查询，与群聊原文分别用于排查执行过程和分析聊天内容。

## 执行与权限

管理对话仅限有效的 WebUI 管理员登录。群管理员验证码、平台消息中的「我是管理员」以及未经鉴权的 Cookie 都不能调用该入口。

页面实时显示工具执行状态，并保留每轮的工具名称、成功/失败和耗时。执行记录不展示原始工具参数或模型上下文；诊断日志不读取 Debug 上下文和任意日志元数据，对已知机器人凭据及常见令牌格式进行脱敏。凭据在「扩展」设置中填写，不应粘贴到对话。

「停止」取消当前任务，离开页面或断开请求也会取消。每轮上限 5 分钟；取消不会回滚已经成功的操作，因此遇到停止或超时，应继续查询实际状态。每个对话同时只允许执行一轮。

每个对话保留最近 40 条消息，刷新页面可恢复当前服务进程中的记录；服务重启后清空。当前进程最多保存 64 个会话，创建新会话时会回收超过 30 分钟未使用且未执行任务的会话。「清空对话」经过页面确认后只删除当前会话上下文，其他会话与已经安装的扩展保留。

管理员管理的是 Diana 的应用能力；执行命令仍以部署进程的系统身份运行，并受到 Agent 的白名单、沙盒和工作目录限制。缺少 Node.js、`npx` 等运行依赖时，助手可以诊断缺失项；实际安装依赖需要对应命令已获授权且部署环境允许。管理对话不能保证修复任意外部服务、网络或系统权限问题，会说明验证结果和仍需处理的条件。

独立安装的本地 MCP 沿用现有 MCP 启动机制，以部署进程的权限运行；`run_command` 的沙盒不覆盖这类进程。安装确认应核对服务来源、启动命令与传入的环境变量。仓库插件声明的 MCP 仍使用插件自己的执行策略。

## 开发验证

```sh
go test ./webui ./model/assistant -run '^TestAdminChat' -count=1
go test -race ./webui ./model/assistant -run '^TestAdminChat' -count=1
cd frontend-next
npm run build
```

该入口随后端与 WebUI 一起构建。源码部署需重新构建并启动修改后的后端与前端；安装旧版完整包不会自动获得尚未发布的代码改动。
