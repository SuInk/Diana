# 聊天查询 Token 用量

机器人主人可以直接问「最近 24 小时用了多少 Token？」或「近一天的输入、输出和缓存命中是多少？」。模型通过只读工具 `llm_usage` 查询实际日志后回答。普通用户和群管理员不能使用，平台群主也不等于机器人主人；工具注册与执行均检查权限。

默认统计当前 Diana 实例全部机器人、全部模型的合计，窗口是查询时刻往前 24 小时，不是自然日。`llm_usage` 支持 `scope=all/current_group/group`、`group_id`、`profile_id` 和 `hours`（1–2160，默认 24）。当前群查询固定当前平台，群查询默认当前机器人，也可显式指定机器人。返回窗口起止时间、记录调用数、输入 Token、输出 Token、总 Token 和缓存命中的输入 Token。缓存命中已经包含在输入量内，不会额外计入总量。

每一次模型调用都会计入：主回复、路由判断、记忆抽取与归纳、图片与表情包描述、OCR、子任务、生图与改图、embedding 向量化、换模型前的可用性探测，以及控制台里的提供商测试和 AI 生成人设。没有挂在某条消息名下的后台调用（建索引、定时任务）也算在合计里。上游没返回用量的调用（按张计费的生图中转常见）照样计一次调用并标记为未报用量，这部分 token 无法计入，所以有这类调用时合计偏少。兼容历史日志动作名称；历史数据无需迁移。日志已清理、调用未提供用量或尚未完成时，不能得到完整消耗，因此该统计不代表供应商账户账单、费用或剩余额度。日志不可用时返回错误，不把查询失败报告成零用量。

## 群聊 Token 排行

群管理页展开“群聊 Token 用量与排行”，可选择最近 1 小时、24 小时、7 天或 30 天，并随机器人范围筛选。按机器人、平台与群 ID 分组，显示调用次数、输入、输出、总 Token、缓存命中和未报用量的调用数；同群的不同机器人不会合并。后台记忆、摘要及定时执行携带来源会话归属。旧日志缺少机器人或群归属时只计入实例合计，不推断归属；合计还包含私聊，因此不一定等于群排行之和。API 为 `GET /api/assistant/llm-usage?hours=24&profile=bot-id`，可附加 `group_id` 和 `platform` 筛选；存储不可用会报错。

## 提供商请求限流

提供商设置可填写“最大并发请求”和“每秒请求上限（RPS）”，两项默认 0 表示不限。正数 RPS 最低 0.001。共用提供商的机器人、模型及 SDK 重试共享限制；请求均匀发出，流式响应读取结束或关闭后才释放并发名额，等待会占用原有请求超时，取消请求也会退出队列。与群额度不同，这是限制实际 HTTP 请求，不是累计 Token 配额。

## 每群模型额度

同一份用量日志还用来卡额度。额度按**群**算而不是按机器人算：一个群刷起来不该把别的群一起饿死。窗口是滚动 5 小时，和订阅套餐的口径一致。

额度只卡**调用次数**。统计口径和上面的查询一致：这个群名下每一次模型调用都算一次，判定、路由和工具步都在内，不只是最终那句回复；上游没报用量的调用（按张计费的生图）照样算一次。以前还有一档 token 上限，已经去掉——按张计费的生图不报 token，token 那档管不到它，而次数对谁都一样好数。

控制台两处都能填：机器人配置里那一档是这台机器人下所有群的默认值，群配置里填了就以群为准，留空或 0 表示跟随机器人。两边都没填才是不限。

群管理列表里每个设了额度的群都带一枚进度角标，过 80% 变色、用满标红；打开群配置能看到这个窗口已用多少、还剩多少。额度用满的表现就是机器人忽然不说话，不把进度摆出来就没人分得清是撞了额度还是坏了。用量读数走和上面查询同一份日志，滚动窗口不在整点清零。

用满之后这个群暂停一切花 token 的环节，消息照常进历史和长期记忆，窗口滚过去自动恢复，不需要手动解除。主人不受限——额度用完还得让主人能改配置，不然就锁死了。读用量失败时放行而不是拦截：日志查不动是 Diana 自己的问题，不该变成对用户的封锁。

## 回复抽样率

额度管的是「最多花多少」，抽样率管的是「平时花多快」。闲聊群里每条消息都要过一次路由模型判断要不要接话，这才是调用次数的大头。抽样率填 30，就只有三成没点名的消息会交给路由模型，没抽中的直接跳过，一次调用都不花，事件中心里写明「未抽中本群 30% 的回复抽样」。

被 @、被引用、叫了名字的消息不参与抽样，照常回复——被点名却随机不理人，看起来就是坏了；这部分由调用次数额度兜底。主人不参与抽样。和额度一样，机器人配置里填默认值，群配置里填了以群为准，留空或 0 跟随机器人，两边都没填（或填 100）就是不抽样。
