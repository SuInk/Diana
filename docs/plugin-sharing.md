# 插件共享配置与订阅目标

插件页的 GitHub 仓库和 RSS 订阅管理始终显示全部已保存订阅，不随侧栏机器人筛选变化。切换机器人只改变该机器人的插件启用状态，以及新增通知目标的默认机器人；不会切换另一份配置或隐藏其他机器人的订阅。任务页仍可按机器人筛选执行记录。

所有插件的参数和凭据全局只保存一份，RSS 订阅和 GitHub 仓库也一样，不提供共享模式开关。在“全部机器人”视图可以统一设置；切换到某台机器人后修改插件参数，修改的仍是同一份共享配置。

插件是否启用仍由每台机器人分别控制。群级启停和既有非密钥行为覆盖沿用原规则，不参与共享凭据的迁移。OpenAPI 继续在系统设置中管理。

## 旧配置升级

- 原来只有全局配置的安装直接沿用原配置。
- 原来按机器人分别保存的配置，按已保存的机器人列表顺序，选取第一个有配置的机器人的整份设置作为共享配置；如果当前机器人列表里没有对应配置，则按旧机器人 ID 排序选取第一份。不会把不同账号的 Token、Cookie 和其他参数拼接成一份。
- 配置页显示迁移来源机器人 ID。其他机器人的旧配置仍保留在存储中作为备份，但不再参与运行。原插件启用状态不变。
- 迁移只执行一次。之后增加机器人会直接使用当前共享配置，调整机器人顺序不会重新选择配置。
- 凭据在读接口中仍只返回“已配置”状态；留空保存不清空已有凭据，只有显式清除才删除当前共享凭据。旧备份不通过接口返回。

## 多目标订阅

RSS 和 GitHub 仓库订阅都可以配置多个通知目标。每个目标包含一个机器人，以及该机器人上的群聊或私聊 ID。例如，同一条订阅可以同时通过 QQ 机器人发送到群聊，再通过 Telegram 机器人发送到频道或私聊。

在订阅编辑器中添加或删除通知目标即可，无需为每个目标重复创建相同的订阅源。每条订阅每轮检查一次来源，再分发通知；不同订阅原有的判断规则和检查间隔不会自动合并。

旧单目标订阅自动以原机器人和会话显示，编辑时可以继续添加目标。目标按机器人与会话去重，同一会话 ID 在不同机器人下仍是不同目标。RSS 会记录本轮已成功投递的目标，失败重试只补投尚未成功的目标；中断恰好发生在平台收件成功与本地记录之间时，仍可能重发。

保存修改会更新整条订阅，因此在某个机器人视图中编辑多目标订阅，也会影响它的其他目标。取消订阅会停止整条订阅；只想停止向一个会话发送时，删除对应目标即可。
