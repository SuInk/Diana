# 怎么看上下文里有什么

两个入口，回答的是三个不同的问题。

## 1. 上下文占比（事件页）

事件页概览里的「上下文占比」卡片，上下两半。

### 比例条：窗口怎么切的

近期历史、会话便签、检索记忆、常驻记忆、自述各分到多少 token，留白多少。它是计划，不是某一轮的实耗；要选中一个群才显示。

### 常驻内容：每轮实际被灌了什么

列出**每轮都注入、与当前消息无关**的几块原文，点标题展开：

| 块 | 内容 |
| --- | --- |
| 品格（soul） | 身份、价值、硬边界，排在最前面，分群覆盖动不了，见 [persona-soul.md](persona-soul.md) |
| 人设正文 | `system_prompt`，只有人能改 |
| 固定提示词规则 | 系统提示词稳定头部里除人设外的部分 |
| 世界书常驻设定 | 标了「常驻」的节点，不含按关键词触发的 |
| 自述 | 机器人自己写的自我认知，默认关闭，见 [self-notes.md](self-notes.md) |
| 会话便签 | 这个会话「聊到哪一步」，选了群才有 |

合计 token 就是这台机器人每轮的底价：什么都没说的时候也要付这么多。不选群按私聊场景取，选了群再叠上分群覆盖和那个会话的便签。

两点要注意：

- 「固定提示词规则」按**全部工具都注册**计算，是上限。实际注入哪几条随当轮注册的工具增减（工具没挂上时对应规则一个字都不注入）。
- 随发言者变化的那段（权限档位、昵称、时段与心情语气、语气锚点）在请求尾部，不在这里；检索记忆、笔记本命中、世界书的触发式设定、跨群召回都要命中当前消息才进；常驻核心记忆按发言者取。这些都不是常驻，摆进来会让人以为每轮都在付这笔钱。

和比例条同层的块用同一个色点（自述、会话便签），一眼对得上是哪一段；人设、固定规则和世界书不在分层里（前两者属于系统提示，落在留白那段；世界书有自己的配额），给的是中性点。

接口是事件概览响应里的 `resident_context` 字段（`webui/assistant_events.go`），15 秒缓存，改完人设最多十几秒就能看到。比例条那半边没选群时不显示，常驻那半边照常按私聊场景给。

## 2. 调试记录（机器人配置里打开调试模式）

打开后每轮回复写一条 `action=context_budget` 的调试记录，这才是**这一轮实际注入了什么**：

- `category_tokens`：按优先级分的实耗（system / plugin_and_tools / memory / summary / history / current）。
- `layers`：层内账——每层拿到几条候选、排序后剩几条、真正写进去几条、为什么丢的（`fits_layer_budget` / `rank_cap` / `layer_budget` / `section_cut`）。
- `categories`：各层拼完之后全局预算再裁一刀的结果。

两者不是一回事：`layers` 能证明「层内配额有没有截断候选」，`categories` 只能证明「拼成的这条消息没再挨刀」。

另有 `action=memory_temporary` 记临时线程状态和会话便签的原文。

## 还没有的

把某一轮**完整请求**（含历史原文和工具定义）原样导出来的入口还没有。现在能看到的是常驻部分的原文，加上逐层的 token 账。
