# 扩展管理

侧栏“扩展”页统一提供插件、Skills 和 MCP 三个标签。原来的插件页地址保持兼容。

## Skills

查看内置、外部目录和受管理的 Skills。可粘贴完整 SKILL.md、选择本地 Markdown 文件，或填写公开 SKILL.md / ZIP 地址导入；受管理的 Skill 支持编辑和删除。内置或外部只读 Skill 不能被覆盖或删除。删除受管理 Skill 沿用原有移入恢复目录的机制，不删除外部源文件。

导入文件需包含 name 和 description frontmatter。Skill 中引用的其他资源应通过 ZIP 包一起导入；仅导入 Markdown 不会自动复制其依赖文件。

## MCP

添加 HTTP 或 stdio 服务，配置 URL、命令、逐行参数、工作目录、请求头或环境变量、超时及工具允许/禁用列表。请求头和环境变量的值读取时不回显，仅列出已配置的键；留空保存保留原值，显式勾选才清除。stdio 默认不继承整个 Diana 进程环境。URL、启动命令和参数作为普通配置可见，令牌应放在请求头或环境变量中。

保存只写配置，不测试连接、不自动运行命令。“测试连接”会访问指定服务，stdio 会启动配置的命令，完成握手和工具发现后关闭测试连接；不会调用发现的业务工具。测试失败不会覆盖已保存配置。演示站不会实际连接 MCP，也不会伪造连接成功。

“服务可用”是全局状态；关闭后所有机器人都不能使用该服务。机器人独立开关不能覆盖全局停用。

每行右侧是一个四档控件：**停用 / 仅主人 / 群管 / 群成员**，表示这一项在当前机器人处于哪一档，默认仅主人。放宽一档需要在确认框里看一遍后果；往回收紧不拦，从开放档切走会同时收回权限，停用后再启用不会悄悄恢复开放。

“群管”只放给群主和群管理员。身份优先用平台事件自带的角色，事件没带才查一次成员信息（4 秒超时）；平台给不出身份、或在私聊里，一律按普通成员处理，也就是不放行。

选中“群管”或“群成员”时，左边会出现一个对象按钮（全部成员 / 全部群管 / 限定 N 人 · N 群），点开可以填用户 ID 名单和群号名单：两个都留空就是这一档的所有人，都填则要同时满足（名单里的人，且只在这些群里）。名单和身份门槛叠加，只收紧不放宽；主人不受任何一项限制。

开放状态保存在 `.extension-overrides.json`，身份门槛和对象名单保存在 `.extension-audience.json`，都按机器人分开。全局“服务可用”仍在编辑弹窗里，关掉后所有机器人都用不了，这一行的四档控件也会置灰。

### 内置预设

MCP 标签里可以从内置预设一键添加服务：预设只决定界面问哪几个字段，装上以后就是一条普通 MCP，改配置、停用、删除都和手填的一样。

目前只有 Gitea 一条，两种接法：

- **用自带的 gitea-mcp**（默认）：Gitea 官方的 `gitea-mcp` 二进制随 Diana 一起发布，Docker 镜像和 Release 包里都放在主程序旁边，填实例地址和访问令牌就能用。令牌按 MCP 环境变量存放，不回显。要换成自己编译的版本，在「可执行文件」里填命令名或绝对路径；留空就是自带的那份，两边都没有时退回 PATH 查找。
- **连接已经跑起来的 gitea-mcp**：自己用官方镜像跑了一份（`-t http`）时填它的地址，令牌配在那一侧，Diana 不经手。

自带的二进制只取 Gitea 官方发布的产物，版本号和每个平台的 SHA-256 钉在 `scripts/fetch-gitea-mcp.sh` 里，对不上构建直接失败；MIT 许可证随二进制一起发在 `gitea-mcp.LICENSE`。升级 Diana 时这份二进制跟着一起换。

### 按群覆盖

扩展页设的是这台机器人的默认档。单个群要不一样时，在“群管理”里编辑那个群，“本群扩展”一栏给每个 MCP 和 Skill 提供三样东西：档位 **跟随 / 停用 / 仅主人 / 群管 / 群成员**（不设就跟随机器人），以及**本群白名单**和**本群黑名单**。

档位选“跟随”表示这个群完全不干预这一项，两份名单也不会出现——要用名单，先给这个群选一个具体档位。切回“跟随”时本群名单一起清掉，不会留下看不见的配置。

判定顺序固定是 **停用 > 黑名单 > 白名单 > 档位**：

- 停用是“这个群没有这个能力”，白名单也放不出来，主人一样用不了；
- 黑名单无条件挡住，压过白名单；
- 白名单是例外放行——名单里的账号不看档位、不看群身份，也不受扩展页那份对象名单限制，专门用来放行“不是管理员但需要用”的那个人；
- 都没命中才看档位，此时扩展页的对象名单继续生效。

两份名单的输入方式和本群屏蔽账号一样：一个账号一个标签，回车或逗号分隔，能查到昵称。

- “停用”对**所有人**生效，主人在那个群也用不了；要恢复回群管理页改回来。
- 机器人级停用优先：扩展页关掉的服务，群里选“群成员”也开不出来。
- 群管理员通过自助配置改这一栏时**只能往严的方向改**：档位不能超过机器人那一档；白名单是放行，只能删不能加；黑名单是拦截，只能加不能删；也不能撤掉本群已有的限制。否则群管理员就能把主人装的服务放给全群。主人自己改不受这条限制。
- 私聊不看群配置，按机器人那一档走。

本群覆盖存在群配置的 `extension_access` 字段里（每项是 `tier` 加 `allow`、`deny` 两份名单），和本群插件开关放在一起。

放开 MCP 前先看清这个服务能做什么：群里任何人都能通过对话触发它，只读查询类服务才适合开放。放开 Skill 的代价不同：正文对群里任何人可读，而 Skill 不会带来新工具，它只会指挥模型去用成员已有的工具（搜索、网页渲染、订阅等）。Skill 目录里带脚本或资源时列表会标出“含脚本”——成员没有命令和文件工具，这部分在成员会话里不会执行，为主人工具集写的 Skill 直接放给成员只会空转。

## 在对话里改

主人在和机器人聊天时可以用 `extension_access` 工具读写开放范围：`list` 看每个扩展的机器人默认档和本群覆盖，`bot_tier` 改机器人默认档，`group_tier` 改某个群的档位，`allow` / `deny` 改某个群的白名单和黑名单（带 `remove` 就是移出）。群号省略表示当前群，账号只认 ID，也可以引用对方的消息。

写操作沿用装卸扩展那套确认流程：第一次调用会被拒绝并给出确认码，机器人要先把将要发生的改动讲清楚，等主人在自己的消息里回复确认码才真正执行；`list` 不需要确认。这个工具只对主人注册，运行时还会再核一次身份。装卸扩展仍走 `mcp_install`、`mcp_uninstall`、`install_skill` 那几个工具，两边不重叠。

## 共享与权限

扩展定义全局一份，侧栏选择机器人后可分别启用或停用每个 Skill、MCP。开关影响后续请求可见的 skill 内容和 MCP 工具，不中断已经开始的会话，也不会关闭其他机器人的 MCP 会话。

启用扩展不等于提权：自定义 Skills 和 MCP 仍受既有 Agent 权限控制。默认只有主人会话可使用这些扩展；普通群成员只可读取内置协议 skill，不会因为启用开关打开就获得自定义 Skill、外部 MCP 或本地命令权限。例外是显式设成“群成员可用”的 MCP 服务和 Skill：成员只拿到这个服务发现的工具、或这一份 Skill 的正文，本地文件、命令、浏览器、其他 Skill 和扩展管理都不跟着开放，能力目录 `list_capabilities` 也仍然只给主人。WebUI 管理接口沿用控制台认证，群管理员接口没有扩展管理权限。

群成员权限与机器人启用开关保存在同一个 `.extension-overrides.json` 里，键名加 `members:` 前缀区分（`members:mcp:<名称>`、`members:skill:<名称>`）。共享底座只有一份：放开后成员用的是主人那套 MCP 进程，不会另起一份。没有任何服务放开给成员时，群消息也不会因此拉起 MCP。

首次访问或启动 Agent 时，将当前运行配置的 Skill 目录和 MCP 配置路径记入工作目录的 `.extension-paths.json`。之后切换机器人不会换用另一套路径；其他旧机器人专用路径不会自动合并。机器人独立开关保存在同一工作目录的 `.extension-overrides.json`。迁移前保留原目录与配置文件，外部文件不会被删除。

修改共享扩展会刷新后续 Agent 注册表。旧的运行中会话使用自己的视图完成处理，新请求读到新配置；外部文件直接编辑后可在界面重新保存受管理配置以刷新。配置有解析错误时明确提示，不宣称工具已经生效。
