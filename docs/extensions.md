# 扩展管理

侧栏“扩展”页统一提供插件、Skills 和 MCP 三个标签。原来的插件页地址保持兼容。

## Skills

查看内置、外部目录和受管理的 Skills。可粘贴完整 SKILL.md、选择本地 Markdown 文件，或填写公开 SKILL.md / ZIP 地址导入；受管理的 Skill 支持编辑和删除。内置或外部只读 Skill 不能被覆盖或删除。删除受管理 Skill 沿用原有移入恢复目录的机制，不删除外部源文件。

导入文件需包含 name 和 description frontmatter。Skill 中引用的其他资源应通过 ZIP 包一起导入；仅导入 Markdown 不会自动复制其依赖文件。

## MCP

添加 HTTP 或 stdio 服务，配置 URL、命令、逐行参数、工作目录、请求头或环境变量、超时及工具允许/禁用列表。请求头和环境变量的值读取时不回显，仅列出已配置的键；留空保存保留原值，显式勾选才清除。stdio 默认不继承整个 Diana 进程环境。URL、启动命令和参数作为普通配置可见，令牌应放在请求头或环境变量中。

保存只写配置，不测试连接、不自动运行命令。“测试连接”会访问指定服务，stdio 会启动配置的命令，完成握手和工具发现后关闭测试连接；不会调用发现的业务工具。测试失败不会覆盖已保存配置。演示站不会实际连接 MCP，也不会伪造连接成功。

“服务可用”是全局状态；关闭后所有机器人都不能使用该服务。机器人独立开关不能覆盖全局停用。

## 共享与权限

扩展定义全局一份，侧栏选择机器人后可分别启用或停用每个 Skill、MCP。开关影响后续请求可见的 skill 内容和 MCP 工具，不中断已经开始的会话，也不会关闭其他机器人的 MCP 会话。

启用扩展不等于提权：自定义 Skills 和 MCP 仍受既有 Agent 权限控制，目前仅主人会话可使用这些扩展；普通群成员只可读取内置协议 skill，不会因为开关开启而获得自定义 Skill、外部 MCP 或本地命令权限。WebUI 管理接口沿用控制台认证，群管理员接口没有扩展管理权限。

首次访问或启动 Agent 时，将当前运行配置的 Skill 目录和 MCP 配置路径记入工作目录的 `.extension-paths.json`。之后切换机器人不会换用另一套路径；其他旧机器人专用路径不会自动合并。机器人独立开关保存在同一工作目录的 `.extension-overrides.json`。迁移前保留原目录与配置文件，外部文件不会被删除。

修改共享扩展会刷新后续 Agent 注册表。旧的运行中会话使用自己的视图完成处理，新请求读到新配置；外部文件直接编辑后可在界面重新保存受管理配置以刷新。配置有解析错误时明确提示，不宣称工具已经生效。
