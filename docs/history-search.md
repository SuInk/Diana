# 历史检索与结果完整性

`diana.chat_history` 默认搜索返回精简命中，不自动携带前后各十条消息。
命中保留时间、发送者身份、消息引用和正文片段；图片仅提供与查询相关的描述片段。
需要核对原文和相邻回答时调用 `around`，传入命中的 `message_id`。
跨群展开还需传 `group_id`，要求跨群记忆已启用，且仍限于同一机器人命名空间。

## 排序与续查

- `order=newest`：默认按时间从新到旧检索。
- `order=oldest`：按时间从旧到新检索；未指定起始时间、hours 或 days 时查全部历史。
- `order=relevance`：保留关键词和语义候选的相关性融合，不承诺穷尽，也不支持精确分页。结果的 `total_is_exact` 和 `search_complete` 为 false。

时间排序在数据库执行，使用时间、创建时间和记录键作为稳定排序条件。
不要从已经截取的最新结果中反转顺序来寻找最早记录。

`search` 续查时原样传回 `next_cursor`，保持 `query`、`scope`、`order` 不变。
游标固定时间范围，并绑定当前会话和查询条件。游标按实际返回条数推进，预算裁掉的命中留待下一页。
`range` 也支持游标；同一秒内有多条消息时，使用游标避免跳过剩余记录。
`next_from_time` 只在时间边界没有重复记录时提供，优先使用 `next_cursor`。

游标固定查询范围，并非数据库快照。查询期间若记录被回填、删除或更新索引，重新搜索可核对变化。

## 完整性字段

| 字段 | 含义 |
| --- | --- |
| `total` | 当前查询的匹配总数；相关性召回时只是已知候选数量，不是完整总数 |
| `total_is_exact` | 是否有可枚举的准确总数 |
| `offset` | 当前页之前已推进的条数 |
| `returned_count` | 本页实际返回的主命中条数，不含附带上下文 |
| `omitted_count` | 总匹配中本页未展示的条数，包含先前页 |
| `remaining_count` | 当前游标位置之后尚未返回的条数 |
| `clipped_count` | 已取到但因本次输出预算被移出本页的主命中条数 |
| `truncated` | 正文、媒体、上下文或命中集合是否被省略 |
| `truncation_reasons` | 具体省略原因，例如上下文删除、描述缩短、主命中延后 |
| `has_more` | 是否还有未返回的命中；非穷尽召回仍保守标为有更多可能 |
| `search_complete` | 当前关键词与时间范围的可枚举结果是否已到末页，不保证事件事实完整 |
| `next_cursor` | 继续读取未返回命中的游标 |

每条命中还可用 `text_truncated`、`quoted_text_truncated`、`media_details_omitted`
指出细节省略。`search_complete=true` 可以与 `truncated=true` 同时出现：所有命中都已列出，但原文只展示片段。

## 输出预算

结果超限时依次移除附带上下文、缩短媒体描述、缩短正文和引用、移除媒体描述，最后才减少主命中。
保持至少一条可引用的精简命中；`around` 优先保住所选锚点。
若异常元数据本身已无法容纳最小结果，显式报错，不能伪装成没有匹配。

模型收到的 `guidance` 会解释计数、续查方式与裁剪含义。
未核对原文或未查完整个范围时，只能说“目前查到最早”，不能断言“最早就是”；
关键词检索完毕也不能证明其他表达方式下不存在更早证据。
