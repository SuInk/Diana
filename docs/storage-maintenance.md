# 缓存与磁盘维护

升级备份只保留本次的一份：下一次升级创建备份前会清除旧备份，新版本健康检查通过后自动删除本次备份；失败时保留用于恢复。安装器选择不启动时暂不删除，源码更新脚本则在构建和文件替换完成后删除临时备份（仍需手动重启，不包含启动健康检查）。若权限等原因导致删除失败，会记录警告，不能视为已释放空间。自行维护的数据备份不受影响。

磁盘维护：文件日志按 20 MiB 轮转，保留 5 份备份；数据库日志在启动后及每 24 小时分批清理，默认调试日志保留 7 天、其他日志保留 30 天。可在 `storage` 下设置 `debug_log_retention_days`、`log_retention_days`，`0` 使用默认值，`-1` 禁用对应清理。旧日志将不可再查看，但用量统计日志、聊天记录、长期记忆、配置和历史媒体不会删除。数据库空闲页供后续写入复用，已有 `.db` 文件不会立即缩小；历史媒体目录和 Docker/系统收集的标准输出日志仍需单独管理，这不是整个数据目录的容量上限。

媒体去重：新写入的历史媒体（含 Telegram 文件、音视频和图片）在各自存储目录内按文件内容 SHA-256 共用一份文件，不再按消息重复落盘；普通图片缓存的远程下载和生图结果也共用内容文件。相同图片 URL 通过持久化来源索引复用；Telegram 优先按同一 API 服务的 `file_unique_id` 在下载前复用，缺失时按同一 Bot 的 `file_id` 复用，贴纸缩略图使用自己的标识。OneBot 图片、视频及文件解析支持的附件支持明确的 `md5`、`file_md5`、`fileMd5` 字段，首次下载核对成功后可跨 URL 复用，不从文件名或不透明文件 ID 猜测 hash。相同来源或稳定标识的并发请求只下载一次；索引最多保留 4096 项，内容丢失或 SHA-256 校验失败时重新下载。不同新地址没有已知稳定标识时，首次仍需下载后判断；MD5 与内容不符时保留可用媒体，但不记录该 MD5 映射。旧路径继续可读，不自动迁移或删除历史重复文件；独立的历史媒体与容量受限的图片缓存不合并，以免缓存淘汰破坏聊天历史。

视频与附件下载缓存位于历史媒体目录的 `download-cache` 子目录，流式下载后按 SHA-256 存储。默认按最后使用时间保留 7 天，不限制总容量。可在 **设置 → 系统 → 下载缓存** 中选择按闲置天数清理、仅按容量清理或永不自动清理；按天数模式可同时启用容量上限。**WebUI 保存后立即生效，无需重启**，已在读取的文件仍受到保护；设置持久化到数据库，重启后优先于 YAML。尚未通过 WebUI 保存时，使用 `config.yaml` 的 `storage.download_cache_retention_days`（0 默认 7 天，-1 关闭按天数清理）及 `download_cache_max_mb`（MiB，0 不限容量）作为启动回退值。YAML 的永不清理组合为 `-1` 和 `0`。启动时、每 24 小时、保存设置及最后一个下载或解析任务释放文件时检查清理。清理不删除历史截图，也不删除 QQ 原始目录中的文件；除永不清理模式外，异常退出遗留的未完成下载在超过 7 天后清理。来源索引仍最多保留 4096 项，仅删除索引元数据、不删除对应文件。缓存命中仍检查文件完整性及当前解析大小限制；淘汰后再次使用会重新下载。公开视频下载与适配器附件的来源索引隔离，保持现有网络访问限制；正文中的普通文件链接仍按原流程读取，不作为固定附件缓存。

## 控制台记录

事件页停留时不自动替换列表，只提示“有新事件”；点击提示或刷新按钮后重新读取。离开页面停止刷新，返回时重新加载，迟到的旧请求不会覆盖当前列表。

人员页的结构化长期记忆列表和计数按机器人及账号精确读取，空机器人 ID 只对应旧版无命名空间记录。可编辑的“最近发言”是排查缓冲，不是结构化长期记忆；删除人员档案保留结构化长期记忆和聊天记录。
