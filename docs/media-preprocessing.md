# 媒体预处理与按需解析

在「机器人 → 行为」的「媒体预处理」里开关每个机器人的自动处理；看图用哪个模型在「机器人 → 模型」的「模型分配 → 视觉理解」里选：

- **自动生成图片描述**：开启时，近期图片进入后台描述队列，供历史搜索和后续上下文复用；关闭时不再自动入队，已排队但尚未开始的任务也跳过。已经执行中的请求可能仍会完成。
- **自动下载视频并提取关键帧**：关闭后，入站、自发消息和发送历史不再为了归档自动解析视频，也不调用 OneBot 的视频文件解析接口。保留原始消息中的视频索引、来源及已有缓存。
- **视觉理解模型**：替对话模型看图的辅助模型，对应 Hermes Agent 的 `auxiliary.vision`。用于图片缓存描述、视频帧描述、表情描述、模型 OCR/画面描述，以及对话模型带着问题回来问图时作答。可以指定视觉模型和显式后备路由；选「跟随对话」时对话模型本身要能识图。

旧配置未填写开关时，两项仍为开启，保持兼容。希望降低日常群聊消耗时，关闭两项并给视觉理解单独指定模型。

关闭自动处理不等于禁止读图或读视频。当前对话需要分析媒体、引用分析或调用 `history_media` 时，仍可以主动读取；历史视频没有关键帧时，工具会按需下载并抽帧，将结果保存供后续读取复用。图片内容哈希缓存和现有队列去重继续生效。图片原始缓存仍会保存，已生成的描述不会被删除。

本地 OCR、文本文件提取不经过视觉理解模型。关闭后台描述后，未主动解析的图片没有文字描述可用于语义检索；远程视频链接过期后，按需读取可能失败，届时需要重新提供媒体。

## 图片交付方式

机器人配置里的 `image_input_mode` 决定对话模型怎么看图，默认自动，界面上不展示，需要时通过配置 API 修改。带图的消息始终由**对话模型**回答，不会整轮换成别的模型。描述本来就会写（后台描述队列、当前图片的描述锚点），所以默认只给描述，要看细节时才看原图，做法对应 Hermes Agent 的 `vision_analyze`：

- **自动（`auto`，默认）**：消息里的图（含引用、语义关联、插件附图、视频关键帧、依赖图）只给视觉理解写的描述。对话模型描述够用就直接答；要确认小字、数量、位置或是谁时调用 `history_media`（不传消息 ID 时默认读当前这条）：
  - 对话模型能看图：原图交给它自己看。工具中途带回的截图也照样交给它。
  - 对话模型看不了图：带着 `question` 让视觉理解代看，只回文字；工具截图在发给对话模型前换成描述。
  - 对话模型能不能看图，先查提供商同步下来的模型清单，清单没写按模型名查随版本打包的 models.dev 目录（`gemini-3.8-flash-low` 这类带思考档后缀的名字按 `gemini-3.8-flash` 查）；都查不到按看不了处理。
- **仅摘要（`text`）**：和自动一样只给描述，但对话模型从不收原图，`history_media` 始终由视觉理解代看。
- **总是附原图（`native`）**：原图始终附上，agent 模式下另附一段视觉理解写的描述。原图和描述是两份 token，agent 每走一步原图还要再发一遍，只在想让对话模型每次都亲眼看图时用。

**要不要单独配视觉理解**：描述总得有个能看图的模型来写。对话模型能看图时，视觉理解保持「跟随对话」就行；对话模型是纯文本模型，或者想让写描述的模型更强或更便宜时，再单独配。描述质量决定了对话模型平时看到的是什么，「猫狗不分」这类问题多半出在描述上。

历史消息里的图始终只以摘要出现，不重放原图。开了「图片文字识别」插件的「仅识别文字」时，不再额外同步识图一次。语音消息仍按原样走多模态路由。

## 从「媒体解析」升级

以前「媒体解析」和「视觉理解」是两档：媒体解析写描述，视觉理解负责带图那一轮的回答。现在带图的消息由对话模型回答，两档合并为「视觉理解」。升级后读取旧配置时：

- 单独绑过媒体解析的，它的提供商和模型移到视觉理解，替换原来视觉理解的设置。
- 媒体解析只是跟随对话、而视觉理解单独绑了的，保留视觉理解。

升级后默认的自动档下，带图的消息改由对话模型看描述作答；以前带图时由视觉理解直接看原图回答的部署，行为会变。想保持对话模型每次都看原图，选「总是附原图」。

机器人配置 API 对应字段：

```json
{
  "auto_image_description": false,
  "auto_video_preprocess": false,
  "image_input_mode": "text",
  "model_roles": {
    "vision": {
      "profile_id": "your-vision-provider-id",
      "model": "your-vision-model"
    }
  }
}
```

提供商 ID 和模型名称应使用当前已配置的真实值。以上只是配置片段，保存配置时需保留其他机器人字段。旧字段 `model_roles.media_parse` 仍然接受，读取时按上面的规则并入 `vision`。
