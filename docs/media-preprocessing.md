# 媒体预处理与按需解析

在「机器人 → 行为」的「媒体预处理」里开关每个机器人的自动处理；用哪个模型解析在「机器人 → 模型」的「模型分配 → 媒体解析」里选：

- **自动生成图片描述**：开启时，近期图片进入后台描述队列，供历史搜索和后续上下文复用；关闭时不再自动入队，已排队但尚未开始的任务也跳过。已经执行中的请求可能仍会完成。
- **自动下载视频并提取关键帧**：关闭后，入站、自发消息和发送历史不再为了归档自动解析视频，也不调用 OneBot 的视频文件解析接口。保留原始消息中的视频索引、来源及已有缓存。
- **媒体解析模型**：用于图片缓存描述、视频帧描述、表情描述及模型 OCR/画面描述。可以指定低成本视觉模型和显式后备路由。独立绑定优先于「视觉理解跟随对话」；配置路由失败时不会隐式改用主对话模型。不配置时沿用视觉理解路由及既有回退规则。

旧配置未填写开关时，两项仍为开启，保持兼容。希望降低日常群聊消耗时，关闭两项并单独指定媒体解析模型。

关闭自动处理不等于禁止读图或读视频。当前对话需要分析媒体、引用分析或调用 `history_media` 时，仍可以主动读取；历史视频没有关键帧时，工具会按需下载并抽帧，将结果保存供后续读取复用。图片内容哈希缓存和现有队列去重继续生效。图片原始缓存仍会保存，已生成的描述不会被删除。

独立媒体模型不替代最终对话模型：最终回答中实际附加的图像仍由视觉理解/对话路由处理。本地 OCR、文本文件提取不经过该模型配置。关闭后台描述后，未主动解析的图片没有文字描述可用于语义检索；远程视频链接过期后，按需读取可能失败，届时需要重新提供媒体。

## 图片交付方式

「机器人 → 行为 → 媒体预处理」里的「图片交付方式」决定回复模型怎么看图，三档对应 Hermes Agent 的 `image_input_mode`：

- **原图（`native`）**：图直接交给回复模型，带图的轮次走「视觉理解」路由。agent 模式下还会附一段媒体解析模型写的描述，帮它对照截图里的小字。
- **仅摘要（`text`）**：回复模型一张原图都不收。消息里的图（含引用、语义关联、插件附图、视频关键帧、工具返回的截图）先由「媒体解析」模型写成描述，描述替换原图；这一轮没有图，由对话模型回答。需要看小字、数量、位置或认人时，模型调用 `history_media` 并写上 `question`，由视觉模型看图作答、只回文字。
- **自动（`auto`，默认）**：「视觉理解」路由的模型在同步下来的模型清单里写明不收图时用仅摘要，写明收图或查不到时用原图。

适合仅摘要的情况：想让识图用好模型、回答按成本选。描述按图片内容哈希缓存，同一张图只识别一次；原图模式下 agent 每走一步都要把原图再发给视觉模型。代价是回复模型看不到像素，描述没写到的细节要靠它主动去问；描述质量取决于「媒体解析」绑的模型。

历史消息里的图两种模式都只以摘要出现，不重放原图。开了「图片文字识别」插件的「仅识别文字」时，原图模式下不再额外同步识图一次。

机器人配置 API 对应字段：

```json
{
  "auto_image_description": false,
  "auto_video_preprocess": false,
  "image_input_mode": "text",
  "model_roles": {
    "media_parse": {
      "profile_id": "your-vision-provider-id",
      "model": "your-low-cost-vision-model"
    }
  }
}
```

提供商 ID 和模型名称应使用当前已配置的真实值。以上只是配置片段，保存配置时需保留其他机器人字段。
