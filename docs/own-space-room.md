# 可视化小窝与 Agent 联动

小窝的「房间与钱包」页在原有账本上方增加夜景卧室，沿用 `/space` 地址。当前采用确认后的鲸鱼娘插画分层与 CSS 动画，不是 Live2D；没有打包开源项目的角色模型。

## 使用

1. 侧栏选择一个机器人，在「机器人 → 人设」中开启小窝。「全部机器人」不读取默认房间或钱包。
2. 打开「小窝 → 房间与钱包」，默认跟随服务端活动。
3. 向启用了 Agent 的机器人说「去你的小窝书桌前坐会儿」「回床边休息」，模型可调用 `room` 工具改变活动。普通聊天不强制调用。
4. 默认跟随 Agent，房间始终展开；主动「接管展示」后才显示手动动作、自定义和减少动画。接管只冻结自动跟随，不暂停后台 Agent，也不会发消息、操作电脑、调用模型或产生支付。
5. 「交还给 Agent」立即恢复最新活动。离开再返回、切换机器人或开关小窝时恢复默认跟随和动画；系统减少动态仍受尊重。切换机器人重置记账草稿。

## 数据链路

`generateReply → room task tracker → RuntimeStatus.rooms → 现有 SSE → roomActivity → roomMotion → 插画图层`

- 回复生成开始时分配独立 task ID，显示 thinking；同步工具开始/结束切换 tool/thinking；回复生成返回时标记 completed、error 或 cancelled。
- 并发回复分别计数，一个任务结束不能清掉其他任务。工具并发计数归属各自任务。
- 此处跟踪的是经过 `generateReply` 的回复生成及同步工具，不是所有后台 worker、异步编码子任务或消息投递。completed 不代表消息已送达。
- Agent 调用 `room set` 选择 rest/phone/desk 后，该选择优先于当时运行中的自动书桌动作。后续新回复任务仍可临时显示书桌，任务结束恢复持久选择。
- `room get` 查看状态；工具不接受目标机器人、URL、命令等额外参数，只操作当前机器人。小窝禁用、任务过期/结束或存储失败时拒绝写入。
- 管理聊天的 session-bound 工具不包含 room；没有具体机器人身份时不能改变房间。

## 协议、持久化与边界

`GET /api/assistant/own-space?profile=...` 返回初始 `room`；现有 status/SSE 返回 `rooms`。快照包含 profile_id、epoch、revision、pose、source、phase、active_tasks、task_id、expires_at、updated_at，不含聊天正文、工具参数和账号身份。

- 同一 epoch 取较新 revision，切换机器人只接受匹配 profile 的快照；服务重启以新的 epoch 为准。
- SQLite 新增 `room_intents`，仅保存每个机器人的目标活动和时间。活跃任务不落盘，重启不会恢复虚假的忙碌任务。
- 活跃状态租期不超过 30 分钟（有更短 context deadline 时用更短值）。超时仅使房间不再宣称执行中，不会擅自终止真实任务。
- SSE 断连、服务停止、缺少快照时静止并提示，不回退到“最近90秒收到消息”的猜测。消息通道断连不代表后台生成一定停止，所以单独提示。
- `status.updated_at` 不是心跳；不以它判断连接是否过期。本地每5秒检查任务租期，不额外请求模型或轮询网络。
- 状态推送复用现有约2秒检测机制；极短任务可能在两次推送之间完成，不保证播放每一个短暂工具状态。
- 钱包审批、支付、余额和动态发布逻辑不变。`room set` 成功只说明目标已保存，不说明浏览器动画已播放完，更不说明真实电脑操作成功。

## 动画与生命周期

连续状态机：放下手机 → 起身 → 走动 → 坐下 → 稳定动作；到达书桌后才显示书桌姿势和灯光。反向目标返回床边。新目标替换旧序列，不无限排队，旧定时器不能结束新动作。

页面隐藏、KeepAlive 停用、系统减少动态或手动减少动画时跳到目标并清理动作计时器；卸载销毁场景。手机窄屏下控制区放在场景下方。固定日光场景不代表实际时间，休息姿势也不代表服务离线。

## 未包含

Live2D 导入、自由装修/寻路、真正打开电脑或浏览网页、多机器人同居、群友访问、购买家具后布置、全后台任务监控。上述能力不能从三个房间动作推导为已经实现。

## 鲸鱼娘插画与用户自定义（2026-11-02）

当前视觉已替换早期 SVG 夜景：使用确认后的蓝白鲸鱼娘、日光木色房间，背景与四态透明角色分层。素材说明见 `frontend/public/room/README.md`。这是 AI 生成的二创表现，不是 DeepSeek 官方模型；动画为静态姿势切换、位置过渡和轻微呼吸/摆动，不是 Live2D 骨骼动画或完整步行动画。

房间右上角「自定义小窝」支持：

- 替换背景，以及休息、手机、书桌、移动四种角色图；未替换的动作沿用默认素材。
- 调整角色大小、床边坐标和书桌坐标，即时预览；预览不向 Agent 发送指令。
- 保存到当前浏览器的独立机器人配置，刷新后恢复；恢复默认先预览，再点击保存确认。
- PNG/JPEG/WebP，每张最多 700 KB、最长边 4096px；建议角色使用透明图。拒绝 SVG、远程 URL 和无法解码的文件。
- 文件只通过 FileReader 和 Image 在本地读取，不上传，不调用模型；异步读取结果不能写到切换后的机器人。存储失败明确提示，不覆盖旧保存。

边界：不同浏览器、设备和站点地址不自动同步；清理浏览器数据会丢失布置。图片不自动抠图、不自动生成动作、不支持 Live2D/3D 导入，背景家具没有单独遮挡层。仅上传一张角色图不会自动变成其他动作；需分别提供对应图片。


## LLM 状态交互与发图（2026-11-02）

`room` 现在有四种操作，均绑定当前机器人的身份，不允许模型指定其他机器人、群或用户：

| 操作 | 行为 | 自然语言例子 |
| --- | --- | --- |
| `get` | 只返回结构化状态，由模型自然回答，不额外发消息 | 你现在在小窝干什么？ |
| `set` | 保存 rest / phone / desk 目标活动 | 去书桌前坐会儿 |
| `report` | 向当前群聊或私聊发送姿势、回复阶段和任务数量 | 发一下你的小窝状态 |
| `snapshot` | 合成默认房间 PNG，通过已有图片通道发到当前会话 | 发一张你现在的小窝状态图 |

状态图只读取打包前端内的固定背景和角色素材，用 Go 在本地合成。图片顶栏标明默认房间、姿势、任务阶段和版本号；它不是浏览器、桌面或摄像头的截图，不包含账户信息、聊天正文或用户浏览器本地自定义图片。无需运行浏览器、无需图像模型，也不会获取任意 URL 或访问模型指定的文件路径。必须使用包含 `room/` 素材的完整 WebUI 构建；缺素材时明确报错，不发送空白占位图。

渲染不持有房间状态锁；发送前重新检查取消、任务是否结束与小窝开关。失败返回错误，只有通道发送成功才返回 `sent: true`。通道发送沿用现有路由与群发送限制；Telegram 沿用临时文件上传，其他平台沿用已有 PNG 投递能力。工具说明要求仅在用户明确索要状态消息/房间图片时使用 report/snapshot，普通询问用 get 后回答，避免重复发送。

验证：Room 相关测试及 WebUI 入口编译在 `-race` 下通过，覆盖三种 PNG、当前会话路由、get 不发送、发送错误、缺少素材、禁止指定其他目标、渲染期间结束/禁用的晚到结果。生产当前主模型 `gpt-6.1-terra` 在隔离记录通道回放 report 和 snapshot，均实际投递一条对应消息；未向真实生产聊天发消息。实际生成的 PNG 已目视核验。
