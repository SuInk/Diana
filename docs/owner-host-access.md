# 主人宿主机访问

在「机器人 → 高级 → 内置 Agent」开启「允许主人操作宿主机」后，主人和对应机器人的 WebUI 管理会话可使用 `host_access`。配置键 `agent_host_access_enabled` 默认 `false`：新建机器人、旧配置升级以及填入推荐默认值都不会自动开启；复制机器人时也会重置为关闭。安全模式仍停用该工具。开关关闭时不注册工具；已经加载的工具每次执行也重新核验权限和开关。

## 能力

- `read`：读取工作区外普通文件，每页最多 64 KiB。
- `list`：列目录，每页最多 200 项。
- `usage`：统计目录逻辑体积，最多扫描 100,000 项，不跟随符号链接，硬链接可能重复计算。
- `disk`：查看指定路径所在磁盘的总量、已用和可用空间。
- `exec`：运行绝对路径的程序和原始参数数组，可显式调用 shell、Python、PowerShell 等解释器。`cwd` 仅为工作目录，不是权限边界。

原生查询不需要审批。受保护配置和凭据的原生读取仍被拒绝，主人账号和配置用 `bot_config` 查询；其返回包含 `owner_id` 和本开关状态。`host_stats` 等原有诊断工具保持原有权限，不受本开关影响。

## 命令审批和执行

每条 `exec` 命令（包括查询命令）都必须审批。Diana 先展示完整程序路径、参数、工作目录和影响，并说明以 Diana 宿主账号直接执行、可以联网、没有沙盒或目录写入限制。主人原样回复 `批准主机操作 <随机码>` 后，Diana 才能重试并执行相同请求。

审批绑定机器人、平台、主人和会话，以及解析后的完整命令参数；五分钟过期，使用一次即消费，重启和重新应用机器人配置后失效。模型参数、历史引用、子任务及“已经批准”的模型自述不能作为批准。WebUI 按管理会话 ID 隔离。

批准后的命令直接在宿主系统运行，权限等于 Diana 进程的系统账号：可联网、安装软件、修改源码或配置、操作该账号有权管理的服务。不会自动获取 root 或管理员权限。该入口独立于 `run_command` 的白名单、工作区写入开关和沙盒设置；Windows 同样支持执行，具体程序取决于宿主安装情况。

这是用户明确选择的完全放权模式，不是强制隔离。运行任意脚本后，无法保证脚本绝对不能修改 Diana、审批数据或进行破坏操作。仍要求模型不执行整机毁坏和绕过主人身份/审批的操作，并对直接调用 `mkfs`、抹盘和根目录递归删除等明显命令做尽力拒绝；这些检查不是对任意脚本的安全保证。原生读取的凭据保护也不能约束获批的宿主脚本。

不再支持 `writable_dir`：传入会拒绝，避免把它误认成写入隔离。命令超时 60 秒，输出最多 64 KiB，取消清理进程组；长任务应通过适合的任务管理工具处理。命令保留常规账号和路径环境，不默认继承 Diana API 密钥或解释器启动钩子。关闭开关会阻止后续调用并撤销待审批操作，但不会撤销已经开始的命令或它造成的改变。

## 验证

测试覆盖默认关闭、配置往返、工具注册、已加载工具禁用、审批失效和单次消费、非主人拒绝、安全模式、真实宿主目录写入和本地网络访问。`TestLiveHostAccess` 用当前生产模型配置进行受测试夹具限制的回放，只允许固定临时文件和固定无害命令，不发送聊天平台消息，也不代表已经部署。

## 能力可见性与权限解释

所有用户都可通过公开能力知识库了解宿主机功能存在；当前身份和访问状态随请求提供，未提供执行工具不等于功能不存在。普通用户不会拿到 host_access 的可调用定义，不能审批或执行；明确无权限时模型可直接解释，无须试调用。capabilities 的 current_access 只返回权限说明，不泄露宿主路径、命令参数或凭据。执行时仍重新核验身份、开关、安全模式与审批，模型的判断不构成授权。
