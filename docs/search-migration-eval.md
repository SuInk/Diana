# 联网调研迁移实测（2026-10-04）

## 实现边界

参照公开 Codex CLI 的工具分工：模型选择搜索、打开页面、查找内容并继续调研。Codex 的 `web_search` 是托管工具；其服务端网页抓取实现不在公开 CLI 源码内。Diana 使用已有的一次性沙盒 Chromium 读取搜索页和原文，没有移植或假称复用了 OpenAI 服务端。

- 默认走浏览器搜索；显式配置的 API 搜索仍可使用，浏览器模式不回退到 Exa/Tavily。
- 查询只规范空白并脱敏，不自动改写名称、版本、引号或 `site:`；多个查询并行执行，共享单次调用 deadline 和提供商预算。
- 搜索只返回候选标题、摘要和 URL。模型选择相关页面，用 `browser_render(url, find)` 阅读；不自动读取排名前两项。
- 删除 claims 账本、结算字段、事实出口门控及终稿复核。实际来源只记录发现、已读、引用状态，不拦截答案。
- 当前轮增加通用联网提醒，防止长聊天历史、人设和玩笑覆盖用户实际请求；没有按产品名称、版本号或测试题硬编码行为。

公开依据：[Codex WebSearchAction 协议](https://github.com/openai/codex/blob/afb436df8b70bb5bc57b86d9a3e829968988cd21/codex-rs/protocol/src/models.rs)、[托管工具声明](https://github.com/openai/codex/blob/afb436df8b70bb5bc57b86d9a3e829968988cd21/codex-rs/core/src/tools/hosted_spec.rs)。10% 联网判断阈值是 Diana 的策略，不能声称它来自公开 Codex CLI 提示词。

## 实测方法

在 miku 使用实际回复模型 `gemini-3.8-flash-medium` 和生产插件设置，调用真实 `Runtime.generateReply`、插件工厂、LLM 和沙盒浏览器。前三例保留原问题的完整 250 条调用方消息，仅由新 Runner 重建自身协议提示。其他场景使用生产人设生成器。测试通道只记录结果，不向群聊发送消息，不写运行数据库，也没有替换生产机器人。

质量评估在答复结束后独立运行，只评估最终答案与实际读取记录，绝不向运行中的机器人回填复核意见。Opus 场景另外读取官方页面作为独立事实参考；它不能算作机器人的已读来源。LLM 评估配合人工检查，有限次数实测不代表所有未来回答都正确。

## 过程中发现的问题

1. 原始回放最初只接梗，没有搜索。加入当前轮的通用提醒后开始调研。
2. 首轮搜索后读第三方文章并补入缺乏正文支持的数字；不能因为发生了搜索就算通过。强化保留实体版本、定位相关官网及数字需正文支持的通用规则后，重新完整回放。
3. 本次新结果格式化代码在超长摘要上发生死循环：截断函数附加标记后仍超限，循环没有进展。改成有界切片，补充大结果集终止、JSON 完整性与输出预算测试。
4. 重定向解析改动曾破坏 Google 翻译链接去重；修复参数解码范围，保留原有翻译链接和新增转义分隔符回归测试。

## 最终回放结果

该轮 8/8 测试流程通过；其中 6 个联网场景的 LLM 质量评分均为正确且有已读来源支持，另外 2 个场景检查没有调用网络工具。这是该轮自动检查结果，不能等同于所有场景经人工查证均正确，后面的新增题目已发现自动评分漏检。

| 场景 | 搜索调用 | 网页读取调用 | 结果 |
| --- | ---: | ---: | --- |
| 原始长聊天中的 Opus 5.5 使用请求 | 3 | 1 | 阅读官方模型目录，确认存在并给出官方 API 用法 |
| 完整历史 + “是不是根本不存在”第一次 | 3 | 1 | 阅读官方模型目录，没有顺着诱导否认存在 |
| 同问重复回放 | 2 | 1 | 再次阅读官方模型目录并确认存在 |
| Code Mode 定义与并行调用 | 2 | 4 | 阅读 Cloudflare 官方文章，解释异步 API 与沙盒聚合 |
| Memoh 搜索服务与并行调研 | 2 | 9 | 阅读官方仓库、架构文档、web.go 与 subagent.go |
| 虚构的 Opus 999.123 版本 | 2 | 1 | 查官方模型目录，回答当前没有该发布版本 |
| 明确不要联网，只解释给定材料 | 0 | 0 | 遵守关闭联网要求 |
| 2 + 2 | 0 | 0 | 直接回答 |

这是工具调用次数，不是底层提供商请求数；同一次 `web_search` 可以包含并行查询。Memoh 案例中首次搜索使用多个 `queries`，实际返回结果后继续选官方源码阅读。重复 find 调用算作网页读取调用，不等于读了多个不同页面。

人工复查仍看到查询质量波动：原始回放中曾生成混入旧型号的查询，随后继续找到相关官网，最终答案正确。Memoh 多次查找同一个源文件、Code Mode 多次查找同一文章，仍有减少往返的空间。本轮没有增加硬编码查询纠正、强制工具选择或回答复核。

代码验证：`go test ./...`、迁移并发/页面选择/来源记录/大输出/重定向测试的 race 检查、前端 `npm ci` 和生产构建、Linux amd64 编译、`gofmt -l .`、`git diff --check` 均通过。没有依赖版本改动；未发布新版本或替换生产服务。

## 复现入口

`model/assistant/search_migration_live_test.go` 通过 `DIANA_SEARCH_REPLAY_BUNDLE` 读取私有 JSON：`Config`（实际回复模型的 ProviderConfig）、`Settings`、`Messages`、`BotConfig` 和 `PluginStates`。该文件含连接配置，必须放在仓库外并限制访问权限。未设置此变量时普通 Go 测试跳过真实网络回放。

```sh
DIANA_SEARCH_REPLAY_BUNDLE=/private/replay-bundle.json \
DIANA_SEARCH_REPLAY_RESULTS=/private/replay-results \
go test ./model/assistant -run TestLiveSearchMigration -v -count=1 -timeout 45m
```

可选设置 `DIANA_SEARCH_REPLAY_CASES` 为外部题目 JSON，字段为 `Name`、`Question`、`Full`（完整历史）、`Search`（应搜索）、`Opus`（使用 Opus 官方评分参考）。解析到新切片，省略的布尔字段为 false，不继承默认题目。新增题目见 `docs/evals/search-effect-cases-20261004.json`。

原始请求、工具返回和完整回答保存为私有测试产物，不能提交到仓库。代码测试还覆盖真实并发启动、部分查询失败保留成功结果、模型自主选择页面、被动来源记录，以及大输出预算。
