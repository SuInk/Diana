# 浏览器控制扩展

这一档让 Diana 操作**用户自己浏览器里的页面**：页面在用户日常浏览器中打开，登录态归用户，Diana 只通过一个用户自己安装、自己授权的扩展下发有限的几条操作指令。

它和[无头浏览器渲染](browser-rendering.md)、[内置浏览器](browser-builtin.md)都是两回事，不互相替代：

| | 一次性无头渲染（`browser_render`） | 浏览器控制扩展（`browser_ext_*`） |
| --- | --- | --- |
| 浏览器 | Diana 自己起的一次性 Chromium | 用户日常使用的浏览器 |
| 登录态 | 没有，每次全新 profile | 用户自己的，Diana 不接触 Cookie 和密码 |
| 用途 | 读公开网页、出图 | 读写用户有权访问的页面 |
| 默认 | 开启 | 全关，逐项授权 |

**不做的事：** 本功能没有指纹伪装、验证码绕过，也没有隐藏自动化痕迹的开关；协议里没有「执行任意脚本」这种指令。它的用途是让用户把自己有权访问的页面交给 Diana 读写，不是用来规避站点风控。用扩展操作页面会在站点侧留下真实痕迹，也可能违反站点的服务条款，这部分责任在使用者。

## 授权模型

要真的能操作一个页面，下面每一项都必须成立，缺一项就被拒：

1. **总开关**：WebUI 的浏览器控制策略里 `enabled` 打开。
2. **来源白名单**：扩展的 `chrome-extension://<扩展 ID>` 在 `allowed_origins` 里。白名单为空时谁都连不上。
3. **令牌**：扩展握手时带一把 WebUI 里签发的令牌。令牌只存 SHA-256 哈希，明文只在创建那一刻显示一次；首次握手时会把它钉在那个扩展 ID 上，换扩展要重新签发。
4. **站点白名单**：目标页面的主机名命中 `allowed_hosts` 且不在 `denied_hosts` 里。白名单为空时一个站点都不允许。
5. **读写档位**：点击、输入、导航属于写操作，要 `write_enabled` 打开；关闭时只剩读取。
6. **按机器人开关**：机器人配置里的 `agent_browser_control_enabled`。默认关闭，逐台打开。这一轮还得轮到扩展当浏览器来源：「浏览器」页里勾选了「我自己的 Chrome」，且排在它前面的内置浏览器用不上或没勾，见文档站[链路 · 浏览器机制](https://suink.github.io/Diana/pipeline#browser)。
7. **浏览器权限**：用户在扩展选项页把白名单里那些站点的权限授给扩展。

另外，`browser_ext_*` 走的是 Agent 工具的关系档位：**只有主人能用**。群成员的工具白名单里没有这组工具，所以别人在群里怎么说都调不动你的浏览器。

前六项在 Diana 侧判断，第七项在浏览器侧——扩展没拿到站点权限时，Chrome 自己就不会让它碰那个页面。

站点白名单写法：`example.com` 只匹配这一个主机名；`*.example.com` 匹配子域但**不含** `example.com` 本身，两个都要就两条都写。单独一个 `*` 不接受。黑名单优先于白名单，可以放开 `*.example.com` 再挖掉 `admin.example.com`。

## 人工接管

用户随时可以按下接管：点扩展的工具栏图标、在扩展选项页按按钮，或在 WebUI 里切换。接管打开之后：

- 控制面不再下发任何指令，工具调用直接报 `takeover`；
- 扩展自己也不执行指令，两侧各拦一道；
- 图标上显示「接管」，状态在重连后保持不变。

## 部署与连接

1. 在 WebUI 的「浏览器」页打开「我自己的 Chrome」，在下面创建一把令牌，记下明文（只显示这一次）。
2. 拿到扩展源码：源码部署直接用仓库里的 `packaging/browser-control-extension/`；容器部署在浏览器控制页点「下载扩展源码包」（也可以直接取 `GET /api/browser-control/extension.zip`），解压到本地。
3. 在 Chrome 打开 `chrome://extensions`，开启开发者模式，「加载已解压的扩展程序」，选上一步那个目录。
4. 复制扩展页面上的扩展 ID，回 WebUI 把 `chrome-extension://<扩展 ID>` 填进「允许的来源」。
5. 填站点白名单，决定是否打开写操作，保存策略。
6. 打开扩展的选项页，填 Diana 的 WebUI 地址和令牌，点「保存并连接」。
7. 点「授权这些站点」，把白名单里的站点权限给扩展。
8. 在要用这一档的机器人上打开 `agent_browser_control_enabled`。

连接是**扩展主动连 Diana**，所以 Diana 不需要能访问用户的机器，只要用户的浏览器能访问 Diana 的 WebUI 地址即可。令牌放在握手帧里而不是 URL 上，不会进访问日志、反代日志和浏览器历史。公网部署请务必用 HTTPS：扩展会把 `https://` 地址换成 `wss://`。

## 工具

| 工具 | 档位 | 说明 |
| --- | --- | --- |
| `browser_ext_tabs` | 读 | 列出白名单内的标签页。清单由控制面按策略筛过，用户其余标签页不可见，也不会打扰扩展 |
| `browser_ext_read` | 读 | 读页面或某个元素的可见文字 |
| `browser_ext_open` | 写 | 在白名单站点内导航 |
| `browser_ext_click` | 写 | 点击元素 |
| `browser_ext_type` | 写 | 填输入框，可选回车提交；密码框会被扩展拒绝 |

页面在导航后跳到白名单外时，控制面会丢掉这次回执的正文，只报「已跳转到未授权站点」——扩展先拦一道，控制面不只信扩展。

**没有截图。** 浏览器的截图接口（`captureVisibleTab`）要么要 `<all_urls>`、要么要 `activeTab`，都是「当前这一页随便读」级别的权限，比「只授权白名单站点」宽得多；为一张图把扩展权限放大到全网不值得。要页面内容用 `browser_ext_read`；要截图就把来源换成 Diana 内置浏览器，用 `browser_screenshot`：它截的是内置浏览器（或机器人配置的外部 CDP 浏览器）里的页面，不经过你的 Chrome。

## 资源开销与限制

- 控制面本身几乎不吃资源：一条 WebSocket，加上按连接缓存的标签页清单，没有浏览器进程。
- 指令默认 20 秒超时（上限 120 秒），每分钟默认 60 条（上限 600 条），单条连接最多 8 条指令同时在飞。
- 单帧上限 8 MiB。
- MV3 的 Service Worker 空闲会被回收，扩展靠一分钟一次的闹钟重连，所以断线后最多约一分钟恢复。重连时控制面会顶掉这个扩展的上一条连接，同一个浏览器只会留一条：否则旧连接要等 90 秒心跳超时才消失，这段时间里工具会因为「有多条连接」而要求点名。
- 同时连多个浏览器时，工具调用要用 `connection` 参数点名，Diana 不替用户猜是哪一个。

## 接口

管理接口在 `/api/browser-control` 下，走 WebUI 会话鉴权：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/browser-control/status` | 策略、令牌、连接与就绪状态 |
| PUT | `/api/browser-control/policy` | 覆盖策略；关掉总开关会当场断开所有连接 |
| GET/POST | `/api/browser-control/tokens` | 列出、签发令牌 |
| DELETE | `/api/browser-control/tokens/:id` | 吊销令牌，并断开用它连着的连接 |
| POST | `/api/browser-control/connections/:id/takeover` | 切换人工接管 |
| DELETE | `/api/browser-control/connections/:id` | 断开一条连接 |
| GET | `/api/browser-control/extension.zip` | 下载扩展源码包（镜像里带了才有，`status` 的 `extension_download` 表示有没有） |

扩展接入端点是 `/browser-control/v1/socket`，不在 `/api` 下：它的鉴权是令牌加来源白名单，跟 WebUI 登录态无关，也不该因为管理员登出就掉线。

## 想要一个 Diana 自己的浏览器？

那是另一档：[内置浏览器](browser-builtin.md)。它不进你的日常浏览器，而是 Diana 自己
常驻一个 Chrome，profile 留在数据目录里，WebUI 里能看画面、能直接上手。要「用我已经
登录好的那个浏览器」就用本页这一档，要「给机器人一个它自己的浏览器」就用那一档。

## 有头容器与远程桌面

有头 Chrome、虚拟显示和 noVNC 只是**可选的部署形态**，不是这一档的前置条件：扩展装在哪个浏览器里都一样连、一样受同一套策略约束。想把浏览器放进容器再用远程桌面看，就把这个扩展装进那个容器里的 Chrome，profile 目录挂出来即可持久化，其余配置与上面完全相同。
