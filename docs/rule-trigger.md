# 规则触发与普通模式

在「机器人 → 行为 → 接话 → 触发模式」选择「规则触发（智能概率，省 Token）」或「普通（固定概率，省 Token）」。两种模式都不调用接话评分模型，共用「随机接话概率」和冷却设置，区别只在未被点名的消息怎么抽签：规则触发按下面的本地信号调整概率，普通模式每条都按设置的概率原样抽签。群管理里的接话设置也可以单独覆盖，或跟随机器人。旧配置继续使用语义判断，不会自动切换。

- @ 机器人、引用回复机器人、命中群聊触发词：沿用现有直接回复流程，不受随机概率和闲聊冷却限制。触发词仍按原有宽松／智能／严格档位匹配。
- 其他群消息：以「随机接话概率」为基础概率决定是否进入回复生成，不调用接话评分模型。默认 30%（概率 0.3）；设为 0% 时只回应明确触发；100% 表示每条符合准入、未被暂停且冷却已结束的候选消息都获得回复机会，不做下面的调整，也不代表一定发出回复。
- 基础概率会按本会话内存里的近期消息和回复疲劳调整，全部在本地计算：
  - 群里聊得快：最近 2 分钟真人发言超过 6 条时，按 6/条数摊薄，最低 0.2 倍，让插话次数跟时间走而不是跟消息条数走；
  - 两个人你来我往（最近 4 条真人发言只来自两人、轮流说）：0.5 倍；
  - 内容很少：去掉表情、图片、@ 和标点后不同的字不超过两个（如「哈哈哈」「666」「好的」、纯表情）：0.3 倍。按字数判断，不维护词表；
  - 对这位发言者的回复疲劳：按疲劳值最多压到 0.3 倍；
  - 问句（带问号，或以「吗」「呢」收尾）：1.5 倍；冷场 10 分钟后的第一句：1.5 倍；
  - 接着跟机器人对话：机器人最近 6 条之内、3 分钟内说过话，而且回的就是这位发言者（引用了他，或机器人那句之前最近的真人发言是他）：2.5 倍。这是为了接住「机器人刚回答完，对方没引用就接着追问」的消息；生产三天里语义模式判为「在跟机器人说话」才回的 334 条（没 @、没引用、没叫名字）里有 69% 满足这个条件。机器人最近 3 条之内说过话、但回的是别人：1.3 倍；
  - 系数相乘，结果封顶为基础概率的两倍，接着跟机器人对话时放宽到 2.5 倍（默认 30% 时最高 75%）。调试记录的判断原因里会写出基础概率、本条实际概率和起作用的系数。
- 群里几秒内连发、攒成一批判断的几条消息，规则触发按每条各自的概率取最高的那条抽签，回复也针对那条：前面是问句、最后一句是「哈哈」时不会只看最后一句。普通模式只按最后一条抽签。
- 随机结果由平台、机器人、会话和消息 ID 确定。同一消息重试不重新抽签；没有消息 ID 时不随机接话。冷却从成功回复后计时，默认 30 秒。
- 这两种模式都不使用语义模式的「回应提问」、闲聊评分档位和补充判据；这些配置保留，切回语义判断后恢复使用。
- 需要机器人语义点名判断的群消息不再调用模型确认，只接受结构化 @ 或引用回复。私聊原有处理不变。

该模式节省的是接话判断调用，不是关闭全部模型调用。回复生成、工具、记忆、媒体处理、连发合并和审核仍按原设置工作；权限、禁言、响应屏蔽、群聊叫停、疲劳和安全审核不会被绕过。命中规则只表示进入回复流程，不保证最终发送。随机复读是独立功能，不受这个概率控制。

与语义模式相比，未点名的提问在 0% 时不会被主动识别；概率大于 0 时规则触发也只看上面这些本地信号，不会理解话题内容是否适合插话，接着跟机器人对话的消息也只是提高概率、不保证回复。以省 Token 为主可先用 0%，需要偶尔参与群聊再逐步提高。

在聊天里，主人或实时核验的群管理员可以让机器人用 `bot_config` 切换：`proactive_mode=rules` / `random` / `semantic` 和 `rule_chance`，群里默认只改本群，`scope=bot` 改机器人默认值。机器人的能力说明（`capabilities` 检索「触发」「省 Token」）也会讲清两层触发，不再只回答触发词档位。

配置保存在 `participation.trigger_mode`（`semantic` / `rules` / `random`）和 `participation.rule_chance`（0–100 的整数百分比）中，复用 `participation.cooldown_seconds`。
