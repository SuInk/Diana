# 规则触发模式

在「机器人 → 行为 → 接话 → 触发模式」选择「规则触发（省 Token）」。群管理里的接话设置也可以单独覆盖，或跟随机器人。旧配置继续使用语义判断，不会自动切换。

- @ 机器人、引用回复机器人、命中群聊触发词：沿用现有直接回复流程，不受随机概率和闲聊冷却限制。触发词仍按原有宽松／智能／严格档位匹配。
- 其他群消息：按「随机接话概率」决定是否进入回复生成，不调用接话评分模型。默认 30%（概率 0.3）；设为 0% 时只回应明确触发；100% 表示每条符合准入、未被暂停且冷却已结束的候选消息都获得回复机会，不代表一定发出回复。
- 随机结果由平台、机器人、会话和消息 ID 确定。同一消息重试不重新抽签；没有消息 ID 时不随机接话。冷却从成功回复后计时，默认 30 秒。
- 规则模式不使用语义模式的「回应提问」、闲聊评分档位和补充判据；这些配置保留，切回语义判断后恢复使用。
- 需要机器人语义点名判断的群消息不再调用模型确认，只接受结构化 @ 或引用回复。私聊原有处理不变。

该模式节省的是接话判断调用，不是关闭全部模型调用。回复生成、工具、记忆、媒体处理、连发合并和审核仍按原设置工作；权限、禁言、响应屏蔽、群聊叫停、疲劳和安全审核不会被绕过。命中规则只表示进入回复流程，不保证最终发送。随机复读是独立功能，不受这个概率控制。

与语义模式相比，未点名的提问在 0% 时不会被主动识别；概率大于 0 时也不会先理解话题是否适合插话。以省 Token 为主可先用 0%，需要偶尔参与群聊再逐步提高。

在聊天里，主人或实时核验的群管理员可以让机器人用 `bot_config` 切换：`proactive_mode=rules` / `semantic` 和 `rule_chance`，群里默认只改本群，`scope=bot` 改机器人默认值。机器人的能力说明（`capabilities` 检索「触发」「省 Token」）也会讲清两层触发，不再只回答触发词档位。

配置保存在 `participation.trigger_mode`（`semantic` / `rules`）和 `participation.rule_chance`（0–100 的整数百分比）中，复用 `participation.cooldown_seconds`。
