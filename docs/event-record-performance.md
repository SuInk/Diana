# 运行记录查询

WebUI 运行记录列表使用 `GET /api/assistant/events?mode=list`，一次加载 30 条，额外读取一条判断是否还有下一页。该请求不扫描整个时间范围的统计或加载记忆正文，Token 用量只查询当前页消息。

列表显示后单独请求 `mode=summary`，返回当前时间范围的统计和会话筛选项。翻页不重复请求统计；服务端对相同查询短暂缓存 15 秒，按完整查询参数隔离，最多缓存 32 份。统计仍加载时显示占位，失败不会显示为零。切换筛选或离开页面会取消旧请求，旧结果也不会覆盖新列表。

长期及临时记忆在展开模型上下文与调用链时才读取。当前页的后台子任务信息保留，以便直接看到任务状态。旧调用方不传 `mode` 时继续返回完整数据。

文件数据库使用 WAL 和独立的只读连接池（最多 4 条）处理记录列表、用量、记忆和调用链查询，写入仍保留单连接。内存数据库及自定义 SQLite URI 保留原有连接语义。增加机器人/时间排序索引和日志动作/消息/时间索引；首次启动需要创建索引，大库升级启动时间可能增加。

这些改动不代表已经定位此前全部数据库超时的根因。消息历史、向量检索、仪表盘、日志、笔记本和记忆查询也使用只读池；事务内查询仍与写入使用同一个事务，领取消息的 UPDATE RETURNING 仍走写连接。记忆候选规范化移到事务开始前，减少持有写连接的时间。

## 入队故障恢复

入队的单次超时仍为 5 秒。失败时，完整事件写到数据库旁的 `<数据库路径>.inbound-retry/`，使用稳定消息身份生成文件名、0600 文件权限、临时文件加 fsync 和原子重命名。独立目录无需取得 SQLite 连接，只有消息入库或待重试文件保存成功才返回接收成功。数据库和磁盘都不可写时返回错误，不宣称消息已保存。

运行时启动后自动恢复该目录；每批最多处理 32 条，正常每 2 秒检查，连续失败指数退避至最多 30 秒。成功入队后删除文件，重放沿用入队去重和出站幂等。进程重启后仍会继续；恢复消息最多补处理过去 24 小时，过期消息按原有过期策略记录并跳过。损坏记录保留为 `.invalid` 供排查，不阻塞后续有效消息。内存数据库和自定义 SQLite URI 无可用文件路径时，不提供磁盘待重试保证。

OneBot 在入队失败后，即使连接未断也会安排自动回补，覆盖失败消息时间并保留原有最长 24 小时边界；此类触发合并并限频为每 30 秒最多一次。Telegram 等平台使用本地待重试文件，不会调用 OneBot 历史接口。恢复审计写库最多等待 250ms，避免数据库阻塞时卡住恢复协调器。

## 数据库诊断

写路径超过 250ms、读路径超过 500ms 时，进程日志输出 `diana sqlite slow`，包含操作名、读写池、总耗时、等待连接时间（`wait_ms`）和执行时间（`exec_ms`）。只按耗时判断：上下文已取消但几乎没花时间的调用不算慢（那是调用方在进来之前就放弃了）；取消且确实慢的照常记录并带上 `context_error`。

`wait_source=conn` 表示等待时间是本次调用自己测得的：事务开始（`.begin_transaction`）的耗时就是排队等写连接的时间，持有事务（`.transaction`）的耗时全部算执行。`wait_source=pool_stats` 表示取自 database/sql 的连接池累计等待增量，同一时间段内别的调用的等待也会算进来，所以 `wait_ms` 是上界、`exec_ms` 是下界——`exec_ms` 很大时可以确定是 SQL 本身慢。

同一操作一分钟内最多输出一行：第一次立刻输出，之后被压下的合并成一行 `count`、`avg_ms`、`max_ms`、`max_wait_ms`、`max_exec_ms`、`context_errors`，在下一次变慢或一分钟到期时输出。日志不输出 SQL 参数、消息正文或凭据，不依赖 `app_logs` 写入，因此可以在数据库异常时排查。

写连接只有一条，只读查询不应占用它。重连回补的会话快照、状态计数、回补水位、积压合并判断、群消息序号缺口、自我笔记、图片描述/识别与语音转写缓存、群风格、群关系图、表情库、生图记录都走只读池；读取后可能紧接着写入并依赖先后顺序的查询（出站幂等、请求去重、别名盐等）仍留在写连接。记忆任务领取先在只读池确认有到期任务，空队列时不再每轮开写事务。回补会话快照由表达式覆盖索引 `idx_message_events_history_sessions` 支撑，不再逐行解析 payload；升级后首次启动要扫描一遍消息历史建立索引，建不成（例如历史里有无法解析的 payload）只记日志、不影响启动。历史检索的 FTS 查询把总数和当前页合成一次求值，分页后再取 payload。

## 验证

运行 `go test ./model/storage ./webui` 检查分页、独立统计、缓存隔离和读写并发；运行 `go test ./model/storage -run '^$' -bench BenchmarkEventBrowsing -benchtime=3x` 比较完整与轻量查询。基准库包含 6,000 条事件、36,000 条用量记录，每页 30 条；本机结果仅供对比，不能代替生产接口测量。
