# RSS/Twitter 订阅与媒体

WebUI 通过「推送方式」下拉框选择「全部推送」「正则匹配」或「LLM 判断」，默认全部推送；正则匹配和 LLM 判断显示并要求填写规则。API/工具的 `judge_prompt` 在全部推送时可留空。全部推送不调用模型筛选，按时间顺序直接推送本次 Feed 中的新条目原文、链接及媒体，不受「单次判断条目上限」限制；选择 LLM 判断时由模型筛选和生成回复，选择正则匹配时按表达式筛选。已有订阅可选择全部推送并清空规则，未修改的已有规则继续生效。首次创建仍以当前 Feed 建立基线，不补发历史条目；上游已从 Feed 移除的条目不会回溯补抓。原文中的 CQ 控制标记会转为普通文字，不能触发群通知或额外媒体发送。

全部推送模式逐条应用媒体限额，所有条目共用 30 秒视频检查预算；规则模式每个来源通知应用媒体限额。

RSS 订阅解析 FxTwitter 时间线时，会保留推文和一层引用推文的照片、MP4 视频及封面。共享 Feed 缓存保存这些媒体字段，但它们不会进入 LLM 判断提示词或判断缓存键。普通 RSS/Atom 附件不在此功能范围内。

通知只附带回复中明确引用的条目媒体；单条更新无需额外引用。照片沿用每条最多两张、每个来源通知最多四张及去重规则。视频每条最多一个、每个来源通知最多两个。

RSS 插件设置中的「视频大小上限」（`video_max_mb`）默认 200 MiB，可设置为 1–2000 MiB，独立于链接解析插件的配置。视频必须来自 HTTPS `video.twimg.com` 的 MP4 地址；封面和照片仍限于 HTTPS `pbs.twimg.com`。

发送前通过有界读取核验视频实际大小，最多读取上限加一个字节；即使服务器未提供或错误声明 Content-Length，也不会因此绕过大小检查。每个来源通知的全部视频检查共用 30 秒预算。视频超限、读取失败或超时时，该条目只附封面；封面无效或缺失时保留文字和原推文链接。超出每次通知媒体数量上限的内容仍可通过原链接查看。

视频使用独立消息发送，避免 OneBot 接入端拒绝与文字或图片混发；正文和配图先发送。

通知保存远程媒体地址，重试沿用已作出的“视频或封面”选择，不依赖临时文件。检查成功并不保证平台随后下载成功：如果平台发送视频失败，仍使用现有待发送通知重试机制，不静默声称已送达。

## 验证

离线回归覆盖缓存往返、判断数据隔离、视频大小边界、未知及错误长度、错误响应、取消、跳转限制及 OneBot/Telegram 出站媒体转换。

真实 FxTwitter 在线测试默认跳过，手动运行：

```sh
DIANA_LIVE_RSS=1 go test -race -v ./model/assistant -run '^TestLiveRSSWatchTwitterVideoDelivery$' -count=1 -timeout=3m
```

该测试抓取真实时间线、命中共享缓存，并分别验证正常上限和 1 MiB 上限下的视频与封面结果。它不会自动发送聊天消息。可选 `DIANA_LIVE_RSS_OUTPUT` 指定本地 JSON 输出路径，导出待测试消息供人工联调。

## 正则与 LLM 规则

`rule_mode` 支持 `all`、`regex`、`llm`。省略时兼容旧订阅：空规则为全部推送，非空规则为 LLM 判断。正则和 LLM 共用 `judge_prompt` 保存规则，正则模式要求合法的 Go 正则表达式（最多 2000 字），保存时验证；不支持前后查找和反向引用。例如 `(?i)release|更新` 匹配忽略大小写的 release 或中文“更新”。

正则对每条新内容的标题和正文匹配，任一位置命中即发送原文、链接和媒体，不调用模型，也不受模型判断条数上限限制。未命中也推进游标；无效的已存规则报错且不推进游标。LLM 模式沿用原判断和回复生成流程。更新时省略规则和类型会保留设置；切换 all 会清空规则。
