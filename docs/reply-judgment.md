# 接话判断：判据与规则

「这条消息要不要回」由人设 YAML 里的 `reply_judgment` 决定：一组判据，每条是「是或不是」或者「评分」，再加一条合成规则。评分提示词、输出格式、结果解析、给判断模型的题目，以及「行为」页上的开关和档位，全都从这份定义生成——在 YAML 里加一条判据，界面上就多一行。

```yaml
reply_judgment:
  rule: directed or chat_in
  shared_note: |-
    用户明确要求停止、同一内容已经回答或正在机械循环时，directed 填 false、chat_in 记 0.00……
  criteria:
    - key: directed
      name: 回应提问
      kind: yes_no
      addresses_bot: true
      question: 当前消息是不是明确在跟机器人说话
      "yes": "@ 或引用机器人；用机器人的名字或称呼叫它……"
      "no": "群友彼此聊天；只是提到机器人会的话题……"
      note: 上下文不足、需要搜索或调用工具，都不影响判断……
      enabled: true
    - key: chat_in
      name: 主动闲聊
      kind: score
      question: 没人找机器人时，插一句是否自然
      anchors:
        - { score: 0.10, when: 两人私聊、争执或已有人在答 }
        - { score: 0.30, when: 普通闲聊，插话可有可无 }
        - { score: 0.50, when: 顺着话题接一句自然但不必要 }
        - { score: 0.70, when: 有开放邀请或明显的梗 }
        - { score: 0.90, when: 群里明确抛出邀请，或机器人刚被调侃、不接反而奇怪 }
      note: 附和、捧场、表达共鸣、顺口接一句本身就是正常闲聊……
      enabled: true
      threshold: 0.70
      cooldown_seconds: 30
```

## 判据

| 字段 | 说明 |
| --- | --- |
| `key` | 小写字母开头，只含小写字母、数字和下划线。规则、输出 JSON、分群覆盖都用它。一套里不能重复。 |
| `name` | 界面上显示的名字。 |
| `kind` | `yes_no`：模型回答是或不是；`score`：模型给 0 到 1 的分。 |
| `question` | 这一条问的是什么。 |
| `yes` / `no` | 仅 `yes_no`：什么情形算是、什么情形算不是。 |
| `anchors` | 仅 `score`：2 到 10 个刻度，`score` 从小到大、落在 0 到 1 之间。模型照着打分；判断模型按档作答。 |
| `note` | 补充说明，可空。 |
| `enabled` | 开关。关掉的判据在规则里恒为假，也不再问模型。 |
| `threshold` | 仅 `score`：分数到这个值才算过线。0 表示不设门槛，但 0 分永远不算过线——那是「叫停」和「机械循环」。 |
| `cooldown_seconds` | 仅 `score`：这条判据让机器人开口之后，同一个群里多少秒内它不再算过线。0 不冷却。 |
| `addresses_bot` | 这条判据为真表示「有人在找机器人」。有它为真的回复是被叫到的回复；全靠其他判据放行的是主动插话，按插话的节奏和语气回复，受群内发言占比限制，模型最终没话说时可以不发。回复循环检测也靠它区分「被点名」和「插话」。 |

## 规则

`rule` 是一个布尔表达式：判据的 `key`、`and`、`or`、`not` 和括号。优先级 `not` > `and` > `or`。每条判据先算成真或假：

- `yes_no`：开着，且模型答「是」。
- `score`：开着，分数大于 0 且不低于门槛，并且不在冷却中。

规则为真就回复。规则里引用了不存在的 key、括号不配对、写了别的符号，保存时报错并指出位置；规则里没用到的判据照样会问模型，只是不影响结果（界面上会提示）。

## 分群覆盖

判据的定义（问什么、怎么判、规则）跟着人设走。分群只能按 `key` 覆盖三样：`enabled`、`threshold`、`cooldown_seconds`。人设里没有的 key 在分群覆盖里会被忽略。

## 生成出来的东西

- 评分提示词：任务说明 + 每条判据一段（问题、是/否情形或刻度、补充说明）+ `shared_note` + 补充判据 + 输出格式。
- 输出格式：一个 JSON 对象，每条判据一个字段——`yes_no` 是 `{"value": true, "reason": "…"}`，`score` 是 `{"score": 0.35, "reason": "…"}`。
- 判断模型的题目：`yes_no` 一道是非题，`score` 一道按刻度作答的评分题。

输出格式由判据生成，不能单独覆盖。
