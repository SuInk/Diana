# 全局状态视图（设计，尚未实现）

“全局意识”不是把所有群塞进一个会话，而是让机器人能有依据地回答：**最近发生了什么、自己实际做过什么、哪些事还没结束、持续关注什么**。本次只提出设计，不新增运行时功能、后台扫描或权限。

## 采用小型、按权限投影的只读视图

每次确定要回复后，从已有事实源生成有限预算的状态块，放在[稳定历史后的动态尾部](group-prompt-cache.md)。第一版用确定性查询和排序即可，不必每条消息额外调用总结模型。需要细节时按引用检索，不把整份跨群档案常驻提示词。

每项至少带来源引用、所属机器人及会话范围、发生时间、有效期和状态；派生缓存还应带来源版本。删除、清空上下文、权限或来源变化应使投影失效。没有记录时应说未知，不让模型补出行动或承诺的完成状态。

| 视图 | 内容 | 事实源与约束 |
| --- | --- | --- |
| 近期活动 | 近期话题、自己的回复与实际行动 | 持久消息、出站事件和工具执行摘要；保留来源时间，不能从回复中的自述推断执行成功 |
| 未完事项 | 已建任务、等待条件、失败或待投递状态 | 任务/订阅实时状态；聊天中的承诺可以标成待确认事项，但不冒充已创建或已完成任务 |
| 持续关注 | 明确保存的目标、偏好、立场与关注点 | notebook 与显式启用的 self_note；不根据每条闲聊自动改写人格 |

## 复用哪些现有机制

### 消息与自身行动

- [消息存储](../model/storage/message_history.go)的 `AppendMessageEvent`、`ListRecentMessageEvents`、`ListContextMessageEvents`：`message_events.payload` 保存完整事件。自动上下文与显式历史检索对 reset 代际的处理不同，视图必须选择符合用途的接口。
- [Runtime](../model/assistant/runtime.go)的 `rememberOutgoingWithMessageID` 保存 `Outbound=true` 的真实出站事件，有平台消息 ID 时保留 ID。
- [工具调用记忆](../model/assistant/tool_call_memory.go)把 `ReplyToolCall` 挂在出站 `MessageEvent.ToolCalls` 中持久化，字段是工具名、摘要与失败标记。它不是完整工具结果或独立审计库：只保留有限次数、过滤内部/未执行调用，拆分回复只挂第一条，订阅推送不挂这份 trace。缺失 trace 不能证明没有执行，存在 trace 也不能忽略失败标记。

因此“我做过什么”应优先读取事件和回执，不读取机器人自己声称“已经完成”的句子作为执行事实。

### 任务与订阅

- [任务工具](../model/assistant/tasks_tool.go)及订阅后端共用 `Reminder` 数据模型，已有最近执行/取消时间、失败次数、最后错误、待投递、下次执行和安全模式暂停状态。
- [SQLite](../model/storage/sqlite_store.go)的 `LoadReminders` / `SaveReminders` 把任务保存为 `app_state` 中 `reminders` 键对应的 JSON；[运行时任务存储](../webui/reminder_store.go)维护内存快照。不要为该视图另造任务表或调度器。
- `scope=all`、查询他人、当前机器人范围，以及 schedule/rss/github 后端的权限和仓库授权必须保留。现有 `mine` 查询刻意跨机器人，与用户额度统计一致，不能直接当成“当前机器人的全部任务”。
- “active”不代表已执行成功或可正常投递；状态必须来自任务事实源，不能用 notebook 的 todo 文本代替。

### 长期笔记与自我观察

- [notebook](../model/assistant/notebook.go)已有 fact/preference/event/todo/person/term 及修订史。默认写入机器人级共享范围，关闭共享后按会话写；读取还包含 legacy global 兼容。视图不能假设所有笔记天然只属于当前群，也不能自行扩大它们的读权限。
- [self_note](../model/assistant/self_notes.go)是按 profile 的跨群自我观察，默认关闭、无身份时关闭。它表达习惯、偏好和自我印象，是不可信记忆而不是权限或任务事实，不应覆盖人设。
- 临时活动应为可重建、可失效的派生视图，不应不断写进 self_note，也不默认自动写 notebook。

## 隔离与跨群边界

先按平台、profile、机器人账号和 namespace 隔离，再按**当前接收者与目标会话的可见范围**投影；机器人曾经看过，不代表当前群可以看见。私聊、凭据、个人便签不默认跨群共享；WebUI 管理员控制面的可见范围单独处理。

现有跨群机制不能简单等同于一个“全部可读”开关：

- [显式历史检索](../model/assistant/history_tool.go)：跨群读取需要开启跨群记忆；私聊入口仅主人，普通成员还需来源群成员资格，查询失败不放行；底层受 namespace 群会话前缀约束。
- [自动跨群上下文](../model/assistant/cross_group_context.go)：仅群聊、同平台、相关性筛选，并校验来源消息作者是当前目标群成员；清除来源群标识、媒体及引用链。它排除机器人出站，因此不等于机器人的跨群行动概览。

新视图不能绕开这些已有边界。若需要新的跨群行动概览，应先明确接收者可见范围再实施；本轮不收窄现有联想作者范围、不挂接话评分、不改变筛选策略，不新增跨群发送或执行权限。

## 参考 Yuki，但不照搬共享范围

[Yuki 源码快照](https://github.com/YuanYeYouTao/Yuki/tree/99ce5a643f1fd6c126bf64af7c8963d1082c3864)的短期状态使用三个小槽位、每槽 300 字符、24 小时 TTL 和 revision CAS，有助于控制状态体积与过期更新。其全局 `short_state` 不按用户/群分区；UNTRUSTED 标记限制指令可信度，却不提供保密隔离。可以借鉴小预算、TTL、来源与版本校验，但不能直接复制全局共享语义。

## 后续实施顺序

1. 定义三类视图的来源、身份/可见范围、有效期、状态与引用结构，并写隔离和撤销测试。
2. 从现有存储确定性生成有限条目；先不加新的后台模型总结和调度。
3. 仅在已决定回复后注入尾部；详情按引用访问，避免改变接话决策或稳定前缀。
4. 验证重启、并发、reset、来源删除、权限变更、任务失败/取消/待投递，以及跨群不可见资料不会泄漏。
5. 在真实使用反馈后再决定预算、刷新周期及管理员 UI，不先建设一套新的“意识数据库”。
