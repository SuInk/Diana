# 复用机器人连接

在 WebUI「机器人 → 新增机器人」中选择「复用某机器人的连接」，即可创建使用同一个 OneBot 平台账号的新机器人配置，无需再次填写地址和 Token。已有机器人也可在「接入 → 连接来源」中切换。支持反向 WebSocket、正向 WebSocket 和 HTTP。

- 独立配置时，填写与其他机器人相同的 WS 地址会立即提示来源，可点击「改为复用」。不会自动切换或复制 Token；主机名大小写、默认端口和根路径末尾 `/` 视为相同地址。保存、单台启用和全部启用也会校验重复连接；已停用的来源同样会提示。
- 卡片显示「复用 · 来源机器人」；来源卡片显示被几台机器人复用。
- 连接地址、鉴权和平台账号跟随来源；修改来源后同步生效。新配置只保存来源 ID，不复制来源密钥。
- 同一连接只建立一次，群消息分别交给每台启用的机器人；人设、行为、群配置及会话命名空间保持独立。同一条群消息只选择一个角色进入处理，其余角色保留消息作为上下文。平台上仍显示同一个账号，可用各自的群准入把不同机器人分到不同的群。
- 私聊、私聊里的通知（如戳一戳）和好友请求只交给连接的来源机器人，避免同一个账号在私聊里连回好几遍；来源停用时交给第一台启用的复用机器人。私聊的人设和私聊准入以这台为准。
- 停用来源机器人只停止它自己的消息处理，其他启用的复用机器人仍可使用连接。全部停用后关闭连接。
- 来源仍被引用时不能删除，也不能改成其他平台或再次复用另一台机器人。先更换使用者的连接来源。
- 仅支持直接引用独立的 OneBot 连接，不支持跨平台或链式复用。

反向 WebSocket 和 HTTP 各自仍只有一个进程级监听器。历史配置中未显式复用的多个独立监听配置仍只接入第一个；如果所选复用来源不是实际接入的连接，保存会提示冲突。不同账号需要独立接入，可使用正向 WebSocket。

## 从已有机器人复制配置

机器人卡片上的「复制配置」，或「新增机器人」里的配置来源选择，可以用现有机器人的人设、模型分配、行为与准入设置生成一份新草稿。保存前可以检查各分区，取消返回列表不会新增机器人。

这是一次性复制，保存后各台独立修改，不会跟随来源同步。新草稿不复制平台账号、头像、Token、接入凭据或消息互通链路，也不会复制历史记录和分群配置。OneBot 可以点击「同时复用来源连接」；来源本身复用其他连接时，会直接选中其独立连接来源。其他平台需要重新配置新账号的接入信息。

## 同群里的角色区分

群聊的选择顺序是：

1. **点名**：匹配机器人名称或触发词。名字和别名建议不要重叠；重叠时优先匹配更长的称呼，同长优先连接来源，再按机器人列表顺序选择。一次只选择一个角色，不因同时叫多人而群发。
2. **引用**：引用同账号的一条消息时，按真实消息 ID 查发送角色。发送归属使用现有送达记录，记录仍在时重启后也可查回；无法识别的旧消息回到默认接待者。
3. **裸 @**：没有点名的 @ 交给连接来源；它停用或不满足本群准入时，交给列表中第一台可用的复用机器人。
4. **普通消息**：没有点名或引用时交给默认角色，仍按其正常主动接话规则判断是否回复。不会因为刚与某个角色聊过，就自动切换后续消息的人设。

明确叫到的角色若停用或不满足准入，不会让其他角色冒名回答。私聊仍按连接来源路由，暂不支持在私聊切换角色。通知和定时推送保持各自的配置，不参加这条群消息的接话选择。

「接入 → 连接来源」旁的 **共享连接时显示角色名前缀** 默认为关。开启后，共享连接中的该角色在群里发送文字会带上 `【机器人名称】`；私聊不加。前缀由程序添加，不依赖模型模仿。不改变 QQ 账号的头像和昵称。
