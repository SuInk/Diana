# 发言偏好

机器人设置的「接话设置」和群管理里有三项，决定没被直接叫到时机器人开不开口。完整的判断流程和流程图见文档站[链路 · 主动接话](https://suink.github.io/Diana/pipeline#proactive)。

- **回应提问**（开关，`participation.relevance_level` 为 `on` / `off`）：对方明确在跟机器人说话时回应。关掉之后只靠主动闲聊开口。@、引用和称呼这类直接触发不受它影响。
- **主动闲聊**（七档，`participation.chat_level`）：没人叫它时多愿意插话。
- **闲聊冷却**（`participation.cooldown_seconds`）：两次主动闲聊的最短间隔，默认 30 秒，0–3600，显式 0 表示不限制。

## 模型怎么打分

接话模型对每条候选只回答两件事，各带一句理由：

- `relevance.directed`：是不是明确在跟机器人说话，只有是或否。这种问题给 0–1 的分数，模型会在 0.45 和 0.55 之间摇摆，程序再拿门槛去切，同一类消息这次回下次不回，所以不打分。
- `chat_in.score`：0–1 的闲聊适合度。锚点是：0.00 对方要求停止、同一内容已回答、机械循环或原样复读；0.10 两人私聊、争执或已有人在答；0.30 普通闲聊，插话可有可无；0.50 顺着话题接一句自然但不必要；0.70 有开放邀请或明显的梗；0.90 群里明确抛出「有人知道吗」「求推荐」，或机器人刚被调侃、不接反而奇怪。

默认打分口径如下，这几段都能在提示词覆盖里改（键名 `routing.participation.*`，见[提示词覆盖](prompt-overrides.md)）：

- 附和、捧场、表达共鸣、顺口接一句本身就是正常闲聊，不因为没带新信息就压低。要压低的只有原样复读（不超过 0.10）和对无法核实的说法编出听起来内行的理由（不超过 0.30）。
- 致谢、结束语和「好的」「草」「666」这类纯反应表示话题在收束，不超过 0.30。
- 只有图片、没有文字也没有问题的消息（表情包、梗图、照片）不超过 0.30。例外：机器人刚要对方发的那张图、图里本身是问题或任务（报错截图、要解的题、要读的文档）、随图文字在问什么。

放行规则：

1. `directed=false` 且 `chat_in=0` 表示对方在叫停或正在机械循环，直接不回，「完全不限制」档也不越过。
2. 回应提问开着且 `directed=true`：放行。
3. 否则看闲聊：分数达到档位门槛、并且冷却已过，才放行。
4. 闲聊放行前还要看机器人最近的发言占比：10 分钟内机器人消息占 25% 以上、至少 3 条且不止一个人在聊时不再插话；「完全不限制」档豁免这一条。

| 档位 | 界面名称 | 闲聊分门槛 |
| --- | --- | --- |
| `off` | 从不闲聊 | 不闲聊 |
| `minimal` | 很少插话 | ≥ 0.90（最严） |
| `low` | 偶尔接话 | ≥ 0.70 |
| `medium` | 适度参与 | ≥ 0.50 |
| `high` | 积极参与 | ≥ 0.30 |
| `extreme` | 频繁参与 | ≥ 0.10（最松） |
| `always` | 完全不限制 | 不看分数，仍受冷却和发言占比限制，不是每条必回 |

档位和门槛是反的：越愿意插话，分数门槛越低。模型决定沉默时程序不擅自放行；输出格式错误、缺项、分数不在 0–1 或理由为空时，先带一条提醒重问一次，仍然解析不出来就沉默。模型出错或超过 60 秒没结果也沉默。

冷却按机器人和会话隔离，闲聊回复真正发出去之后才开始计时，只限制下一次主动闲聊，不拦截提问和点名请求。模型已经允许但仍在冷却时，日志会单独说明。

## 旧配置

没有 `relevance_level` / `chat_level` 的旧配置按原来的主动程度折算：关闭 → 回应提问和闲聊都关；低 / 中 / 高分别对应闲聊档 `low` / `medium` / `high`；极高对应 `always`。旧的五维数值、`relevance_threshold` / `substance_threshold`（0–100）只在上游还按旧 `should_reply` JSON 格式回答时才生效，新格式的评分不再读它们。`proactive_reply_threshold` 仅保留为[发送前审核](https://suink.github.io/Diana/pipeline#audit)里主动回复的发送置信度门槛，不是接话门槛。

群级发言偏好为空时整组跟随机器人。发言档位不影响消息分条、合并转发、账号安全审核、语义去重以及 RSS 订阅通知。`proactive_reply_route` 日志记录两项评分与理由、生效档位、是否放行、是否重问过、冷却和原始输出。分数是模型对语义的判断，程序校验范围与门槛，不能保证模型本身评分准确。

## 补充判据

接话评分的提示词内置，但本群特有的称呼、黑话和禁区可以自己写：机器人设置页和群管理的“接话设置”里各有一个“补充判据”输入框，对应配置字段 `proactive_reply_extra_criteria`，最多 1000 字。群级填了就只用群级的，留空跟随机器人；群把接话设置切回“跟随机器人”时，本群判据一并清空，不留看不见却仍然生效的文本。

补充判据拼在内置评分提示词尾部，只用于理解本群语境，不替代评分口径、不改变档位和门槛，也不新增输出字段——这条链路解析失败的兜底是整群沉默，所以只追加、不开放整段覆盖，判据之后还会重申一遍裸 JSON 输出契约。`proactive_reply_route` 日志的 `custom_criteria` 标明本次评分带没带判据，用于区分“带了判据后沉默”和“模型自己判成沉默”。

## 连续消息合并

“合并回复置信度阈值”是独立于主动接话档位的配置。可填 1–100%，机器人未设置时默认 75%；群级留空（API 值 0）跟随机器人的当前设置，机器人更新后自动生效。

仅在同一用户的回复仍在生成时，模型将新消息判为重复、补充或纠正且置信度达到配置值，才允许合并。调低会更容易合并，也会增加误合并风险；独立问题、无法确定、超时或无效响应始终不合并。已发送的回复不会重新合并，缺少图片内容导致的无法确定也不会被低阈值强行放行。

配置字段为 `reply_merge_confidence_percent`；合并判断日志中的 `merge_threshold` 记录当次实际使用的阈值（0–1 比例）。此配置不影响合并转发卡片的字数或块数阈值。
