# 发言偏好

所有档位的主动闲聊都要求有实质性内容：能补充具体有用的信息、纠正或贴合上下文的新观察、观点、笑点。仅仅“衔接自然”“适合接梗”、附和复读、泛泛安慰和描述表情包不足以放行。纯表情、贴纸、动图和单独图片默认不主动接话；明确要求看图、按机器人要求补图和正常追问仍按请求处理。接话模型对“与机器人相关度”和“内容实质性”分别给出 0–100 整数分与理由，不取平均。闲聊必须有完整有效的两项评分，且实质性达到所配置的门槛（默认 60 分）；高相关度不能补偿空洞内容。直接相关分类的相关度也须达到所配置的门槛（默认 60 分），但明确请求不套闲聊实质性门槛。缺少评分的旧格式仅兼容明确请求，不能放行闲聊。

机器人设置的人设页和群管理提供低、中、高、极高四档回复欲望。另外，“与机器人相关度门槛”和“闲聊实质性门槛”也各有低、中、高、极高四档，分别对应 40、60、80、90 分，默认“中”。门槛越高越严格，和回复欲望越高越主动的含义不同。切换欲望档位、任一门槛或冷却都不会改动其他设置。群选择“跟随机器人”时整组继承，选择独立档位后可以分别调整两个门槛。

低：偶尔补充有用信息，尽量不打扰。中：自然参与，适当接话，聊完收住。高：更主动接话，参与闲聊和后续讨论。极高：积极参与分享和玩梗，也更愿意继续聊。群可以选择自己的档位，也可以跟随所属机器人的当前配置。

四档各自对应一段接话规则。为兼容旧配置，仍保留历史字段，但运行时只用主动程度折算档位，不再把五维数值交给模型评分。旧自定义配置按主动程度就近折算为低（1–37）、中（38–62）、高（63–87）、极高（88–100）；原有关闭状态继续保留，明确请求仍可回应。冷却单独保留。

模型根据当前档位规则和上下文直接返回 `should_reply`（是否接话）、`category`（交流类型）、`target_message_id`、`turn_message_ids`、两项 `scores` 和简短的 `reason`。`scores.relevance`、`scores.substance` 均包含 `score` 与 `reason`。不恢复五维平均分，也不做随机采样。模型决定保持沉默时程序不擅自放行；决定接话后还要通过当前机器人或群配置的分数门槛，再检查独立冷却。格式错误或只有旧评分、没有明确布尔决定的响应不会放行；无效或缺失任一分数、非整数、超出 0–100 或缺少单项理由的评分响应不会放行；高分也不能覆盖 `should_reply=false`。

极高也不要求每条消息都回复。明确向机器人提出的请求仍正常处理，停止请求、重复回应、平台权限和准确度审核仍然生效。发送前准确度审核的 `should_send` 与接话判断独立。

主动闲聊冷却是独立配置，默认 30 秒，可设置为 0–3600 秒，显式设置 0 表示关闭。切换回复欲望档位不会修改冷却时间；修改冷却时间也不会改变欲望档位。冷却按机器人和会话隔离，成功发送主动闲聊后才开始计时，仅限制下一次主动闲聊，不拦截公开提问和点名请求。模型已经允许但仍在冷却时，日志会单独说明。

旧档位和回复模式折算为语义偏好，并保留旧的正数冷却时间；未设置冷却时使用 30 秒。旧的意图提示词、社交性回应开关、插话置信度和随机采样不再决定是否发言。原配置字段保留用于读取旧版本数据；新配置以 `participation` 对象为准，冷却字段为 `cooldown_seconds`，门槛字段为 `relevance_threshold` 和 `substance_threshold`。旧配置缺失门槛时默认 60；接口保存 0–100 的数值，显式 0 保留，超界值限制到合法范围。界面以等级选择，已有非预设数值显示为自定义并保留，不自动改写。群级发言偏好为空时，整组跟随机器人。显式设置为 0 的新配置会保留该字段，保存和重新加载后仍表示关闭冷却。`proactive_reply_threshold` 仅保留为发送前准确度审核阈值，不再是意图门槛。

发言档位不影响消息分条、合并转发、账号安全审核、语义去重以及 RSS 订阅通知。日志记录生效档位、两项分数与理由、内容门槛、接话决定和冷却，事件原因显示未放行的具体原因。分数是模型对语义的判断，程序校验范围与门槛，不能保证模型本身评分准确。

## 连续消息合并

“合并回复置信度阈值”是独立于主动接话档位的配置。可填 1–100%，机器人未设置时默认 75%；群级留空（API 值 0）跟随机器人的当前设置，机器人更新后自动生效。

仅在同一用户的回复仍在生成时，模型将新消息判为重复、补充或纠正且置信度达到配置值，才允许合并。调低会更容易合并，也会增加误合并风险；独立问题、无法确定、超时或无效响应始终不合并。已发送的回复不会重新合并，缺少图片内容导致的无法确定也不会被低阈值强行放行。

配置字段为 `reply_merge_confidence_percent`；合并判断日志中的 `merge_threshold` 记录当次实际使用的阈值（0–1 比例）。此配置不影响合并转发卡片的字数或块数阈值。
