# 判断模型（Jev）

意图识别问的本来就是「是不是在跟机器人说话」「这句插得自不自然」「哪一条值得回」。以前只能让对话模型把答案写成一段 JSON，程序再解析回来——上游多吐几个字符、输出被截断，整条判断就作废。TypeSafe 的 System One 模型 Jev 只回答有类型的题目并返回校准概率，不生成文本，正好对上这类用途。

## 接入

WebUI 的模型配置里，接入类型选「TypeSafe 判断模型（Jev）」，地址默认 `https://api.typesafe.ai`，模型填 `jev-latest`。它走的是 `POST /v1/systemone`，不是 OpenAI 兼容接口，也没有模型列表端点，固定版本号需要时手填。

## 只能绑判断类用途

「意图识别」是一档模型分组，底下挂着十几个用途，其中上下文压缩摘要、记忆提取与归纳、关系评估和几种发送前提示改写都要模型写字。整档绑到 Jev，这些用途会直接失败。

因此只把判断类用途单独绑过去，在模型绑定里按用途选：

- `proactive_reply_router`：要不要主动回复、是不是在跟机器人说话、闲聊适合度。
- 其余需要文本输出的用途保持绑对话模型。

绑错了不会静默降级：调用会返回「绑定的是只做判断的模型，它不生成文本」，并指出是哪个用途、该怎么改。

## 判据只有一份

对话模型读的是提示词里的评分规则，Jev 读的是逐题的 `criteria`，两边用的是同一组常量（`participationRelevanceTrue`、`participationChatInLevels` 等）。改判断口径只改一处，不会出现「同一个群换个模型就换套标准」。

闲聊分的锚点（0.00/0.10/0.30/0.50/0.70/0.90）是 Jev 的档位列表，返回的加权档位均值按锚点线性插值还原成 0~1 的分数，阈值和冷却完全不变。

「在跟机器人说话」是一道是非题，Jev 给的是概率，程序按 0.7 切成是否：拿不准（0.5 上下）算否，和文本模型判据里的「拿不准就填 false」同一口径。其它是非题仍按 0.5 切。日志里的「是（0.63）」记的是原始概率，复盘时看得出差一点还是差很多。

## 边界

- **没有理由文本。** 日志里的 reason 由程序按「结论 + 概率」合成，够复盘用，但不会有模型写的那句话。
- **看不到图片。** Jev 只吃文本，消息里的图片在 state 里变成一条 `[图片 ×N，判断模型看不到画面]` 标记。依赖看图判断的场景仍应绑对话模型。
- **没有工具调用。** 带工具的请求会被直接拒绝。
- **多选拆成多题。** `turn_message_ids` 这种数组答案由逐条候选各问一次是非题拼出来，候选越多题目越多。
