# 更新通道

在 WebUI 版本面板中选择更新通道，设置会保存在数据库中，重启后继续生效。旧配置默认使用 Release。

切换通道前会弹出确认：切到 Beta 或 Canary 时说明会收到哪些预发布版本，开启了自动安装时额外提醒会自动装上；切回 Release 时说明不会自动降级。版本面板的版本历史只列出所选通道能更新到的版本，规则与服务端挑选更新候选相同，当前运行的版本始终保留。

| 通道 | 可接收的版本 |
| --- | --- |
| Release（默认） | 正式版，例如 `v0.8.127` |
| Beta | Beta 测试版、RC 候选版及正式版，例如 `v0.8.127-beta.1`、`v0.8.127-rc.1`、`v0.8.127` |
| Canary | 以上全部，再加每次合并到 main 自动构建的 Canary 版，例如 `v0.8.128-canary.3` |

Canary 未经人工验证，适合想第一时间用上刚合并改动的实例。旧版客户端不认识 Canary 通道，需要先升级到支持它的正式版再切换。

RC 只是可选的预发布阶段，不是独立的更新通道。通常直接从 Beta 发布正式版即可。

检查更新、手动下载、后台自动下载和安装都使用所选通道，在最近 30 条 Release 中按版本号选择最新的匹配版本。版本先比较主、次、修订号，同一基线按 `beta.2 < beta.10 < canary.1 < rc.1 < 正式版` 排序，构建元数据不影响排序。草稿和其他未支持的预发布标签不作为更新候选。

切换通道不会自动降级。例如当前运行 `v0.8.128-beta.1`，正式版只有 `v0.8.127`，切回 Release 后会等待更高版本；需要立即退回时可使用现有的稳定版回退入口。切换后必须重新检查，其他通道已下载的包不能直接通过普通安装入口安装。后台更新执行期间修改策略会提示稍后重试。

自动下载、自动安装仍由各自开关控制。源码构建仍需显式选择切换，Docker 部署仍由部署环境更新镜像。GitHub 不可用时现有静态清单回退可能只包含正式版，不能保证发现最新 Beta；恢复连接后重新检查。

## 发布

### Canary

每次推送到 main（即 PR 合并）时，CI 自动发布 Canary，无需改 `model/version/VERSION` 或手动打标签。版本号取最新正式版的下一个修订号，序号取该基线已有 Canary 的最大值加一：最新正式版为 `v0.8.127` 时，依次发布 `v0.8.128-canary.1`、`v0.8.128-canary.2`……发布 `v0.8.128` 后从 `v0.8.129-canary.1` 重新开始。

Canary 标签由 CI 在合并提交上创建，标记为 GitHub Prerelease，不设为最新 Release；产物和校验流程与正式版相同。更新说明只写提交和改动摘要，不走 AGENTS.md 里正式版的中文说明流程。手动推送的 `-canary.N` 标签会被 CI 拒绝。发布正式版时，CI 会删除基线不高于该正式版的 Canary Release 及其标签，避免它们占满更新器查看的最近 30 条 Release；手动发布的 Beta 和 RC 不受影响。

按版本排序，Canary 高于同一基线的 Beta。Canary 通道的实例已经运行 `v0.8.128-canary.5` 时，之后手动发布的 `v0.8.128-beta.1` 不会被安装；它会继续接收更高的 Canary、RC 和正式版。

### Beta、RC 与正式版

普通更新继续只递增 patch。以最新正式版 `v0.8.126` 为例：

1. 将 `model/version/VERSION` 更新为 `v0.8.127-beta.1`，完成验证和 PR 合并后，从默认分支的合并提交创建同名标签。
2. 后续测试版使用 `v0.8.127-beta.2` 等标签。需要候选阶段时可用 `v0.8.127-rc.1`。
3. 发布正式版时将源码版本改为 `v0.8.127`，按相同的验证和合并流程发布。每次标签必须与源码 VERSION 完全相同。

CI 自动将 Beta/RC 标记为 GitHub Prerelease，不设置为最新正式 Release；完整包、SHA256SUMS 和 latest.json 与正式版使用相同的构建和校验流程。latest.json 包含 prerelease 标记。中文更新说明、平台产物检查和下载校验仍按 AGENTS.md 发布要求完成。

Docker 保留每个完整版本标签（及对应的 `-slim` 标签）。正式版更新 `latest` / `latest-slim`，Beta 和 RC 更新 `beta` / `beta-slim`，Canary 更新 `canary` / `canary-slim`；预发布不会覆盖 latest。需要修正或回退 `latest` / `latest-slim` 时，手动运行 `Docker Retag Latest` 工作流并填入已发布的正式版标签，它会把两个标签重新指向该版本的完整版和 slim 镜像，不重新构建。默认安装脚本仍安装正式版，完整包用户安装后可在版本面板切换 Beta；Docker 用户使用 `ghcr.io/suink/diana:beta`、`ghcr.io/suink/diana:canary` 或具体版本标签，并由原部署环境拉取和重建容器。
