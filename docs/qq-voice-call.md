# QQ 语音通话

主人用 QQ 给机器人打语音电话，机器人自动接起来实时对话。通话用的是和 WebUI 电话按钮同一套引擎（[实时语音通话协议](voice-call.md)）：人设、记忆、私聊记录都和主人的 QQ 私聊是同一份，回复只念出来，不发 QQ 文字。

第一版只接主人的电话，也不会主动拨号。

## 为什么要这样绕

QQ 的语音是闭源的音视频 SDK，协议不开放，没法自己写一个客户端去打电话。能做的只有让真正的 QQ 客户端去接，再把声音从中间掏出来。SnowLuma 容器里跑的正好是真的 Linux QQ（3.2.x，带 `avsdk` 语音组件），它的音频走 PulseAudio，所以在容器里建两条虚拟声卡就能接上：

```
对方说话 → QQ 扬声器 → qq_speaker（虚拟）→ qqcall-agent 录音 → Diana 转写、回复、合成
机器人说话 ← QQ 麦克风 ← bot_mic（虚拟）← qqcall-agent 播放 ← Diana
```

`qqcall-agent` 在容器里管窗口和声卡，Diana 的「QQ 语音通话」插件（`model/assistant/qq_voice_call_plugin.go`）连着它决定接不接、对话。两者之间的协议在 `model/qqcall`。

## 一通电话的流程

1. 有人打来，容器里弹出标题为「语音通话」的窗口。agent 截下昵称那一块做 OCR：有「邀请你」字样才算来电（自己拨出去的不管），把昵称报给 Diana。窗口刚弹出时字常常还没画出来，agent 每 0.3 秒认一次，最多认 10 次。
2. Diana 检查接电话的前提：选好了机器人、填了主人账号、模型分配里配了语音识别和语音合成、本机有 ffmpeg。缺一样就不接，并私聊告诉主人缺什么。
3. 前提齐了就等「响铃多久后接听」设定的秒数，让 agent 点接听。**昵称不参与判断**：OCR 认不准表情、特殊符号和被截断的长备注，拿它挡电话会让主人的电话经常没人接。
4. 接通后 QQ 开始从虚拟麦克风采集，agent 据此判断接通，并从 SnowLuma 日志里读对方的 QQ 号：接通那一刻 QQ 会推一条 `msgType=529/11` 的私聊，SnowLuma 解不出内容，只记一行日志，`from` 就是对方。
5. **身份核对**：这个 QQ 号必须是主人。不是主人就立刻挂断；6 秒内读不到也挂断，并私聊告诉主人。
6. 开始对话。对方的声音按 20ms 一帧送进通话引擎，静音分句、转写、回复、逐句合成，合成好的一句转成 PCM 送回 agent 播给 QQ。
7. 任何一方挂断，通话窗口关闭，会话结束。超过「单次通话最长」自动挂断。机器人也能自己挂：对方道别时它说完最后一句，Diana 按已经交给 agent 的音频时长等这句播完，再让 agent 点挂断。

**断线重连**：Diana 和 agent 之间断开（比如 Diana 升级重启），QQ 那头的电话还通着，这边的会话保留 60 秒。agent 连回来会报「有一通已经接通的电话」：同一通就接着说；Diana 重启过、这边没有这通，就核对对方 QQ 号，是主人才重新开会话接着聊。超过 60 秒没连回来，或者 agent 报电话已经挂了，这边才结束。断开期间说的话和要念的句子会丢掉。

响铃时 QQ 不推任何带 QQ 号的东西，所以只能「先接、接通后按 QQ 号验」。别人打给机器人会被接通几秒再挂断，机器人不会对他说话。

## 私聊来电和群通话

两种来电弹的是同一个「语音通话」窗口，只有昵称下面那行字不同：私聊是「邀请你语音通话」，群通话是「邀请您加入"群名"的语音通话」。agent 看到「邀请你/您」就把 OCR 原文（`text`）连同昵称报给 Diana，由 Diana 判断：

- 交给模型（用途「QQ 来电识别」，归回复辅助）：给它 OCR 原文和机器人所在的群（`get_group_list`），让它说是不是来电、私聊还是群通话、谁打的、哪个群。OCR 会断行、丢引号，长群名会被截成「Diana种子用户 (sls...」，窗口上的提示条也会混进来，写死关键词靠不住。模型给的群号必须在群列表里，不在就当没认出来、不接。
- 模型不可用时退回规则：按那行固定文案认，群名去掉省略号和引号后，整名相等或只有一个群以它开头才算。
- 旧版 agent 不带原文，只在认出「邀请你」时报来电，一律按私聊处理。

插件设置里两个开关：「接主人的私聊电话」默认开，「接群语音通话」默认关。群通话：

- 接通后不核对 QQ 号：群通话接通时没有 529/11 推送，agent 也不等这 6 秒。
- 按那个群的身份对话：听到的话当成群里有人对机器人说的，发言人统一记成「群通话」（混音里分不出是谁），提示词换成「QQ 群语音通话」那段。群里没开回复（比如不在白名单）时机器人不会开口。
- 不往主人私聊里记通话记录。
- Diana 重启后不会续上群通话：重连时 agent 报的接通电话没有群信息，只续主人的私聊电话。

## 出了问题怎么知道

- **插件页**：卡片上显示「运行正常」或「N 个问题」，点开设置能看到每个问题和怎么修，以及最近一通电话的处理结果。ffmpeg 列在「运行依赖」里，缺了可以一键安装。
- **机器人自己知道**：电话因为前提不齐没接、接通后读不到 QQ 号、令牌不对、agent 报错时，机器人私聊告诉主人原因。同一个问题 6 小时内只说一次。这条消息在私聊记录里，主人回头问「电话怎么没接」时机器人看得到；它查插件设置（`bot_config`）时也会拿到同一份运行状态，非凭据的设置可以直接在聊天里让它改，令牌这类凭据走 `console_config` 暂存确认。

## 部署

### 1. 准备带语音组件的 SnowLuma 容器

SnowLuma 容器里要额外装上 PulseAudio、QQ 语音插件缺的 `libpulse-mainloop-glib0`（缺了它点「语音通话」不报错，过一会儿显示「已取消」，对方根本没响铃）、xdotool、tesseract 简体中文和 `qqcall-agent`，并让 agent 和 QQ 以同一个用户跑在同一个 X 屏幕上。

这个镜像目前不公开分发：SnowLuma 的许可协议规定，把它的专有组件并入第三方 Docker 镜像需要作者书面授权。在拿到授权或上游直接支持之前，只能自己在 SnowLuma 镜像上构建、自己用。

容器参数照旧，再加环境变量 `QQCALL_TOKEN`（和下面插件里的令牌一致）和端口 6190（只给 Diana 访问）。**换镜像要重建容器，QQ 会重新登录**；数据卷保留时一般能快速登录，不行就扫码。

### 2. 打开插件

插件页「QQ 语音通话」默认关闭。打开后填：

| 设置 | 说明 |
| --- | --- |
| qqcall-agent 地址 | `ws://127.0.0.1:6190/ws`；同一个 compose 里写 `ws://snowluma:6190/ws` |
| qqcall-agent 令牌 | 和 `QQCALL_TOKEN` 一致。留空时自动读 Diana 这边的环境变量 `QQCALL_TOKEN`，或数据目录（数据库所在目录）里的 `qqcall-token` 文件：同一个 compose 里给两边配同一个 `QQCALL_TOKEN` 就不用填；原生安装把令牌写进 `data/qqcall-token`，下次重连就生效 |
| 接电话的机器人 | 下拉框选容器里登录的那个 QQ 对应的机器人，只列 OneBot 机器人；选「自动」用启用了插件的第一台 |
| 响铃多久后接听 | 默认 2 秒 |
| 单次通话最长 | 默认 30 分钟 |
| 允许打断 | 默认开：对方说的话转写出字后，按新说的话生成回复，新回复出声时打断正在说的那一句 |

机器人要填好主人账号，模型分配里要配好「语音识别」和「语音合成」，和 WebUI 打电话的前提一样。

## 已知限制

- **没有回声消除**：虚拟声卡不经过系统的回声消除。对方外放时，机器人自己的声音可能经对方手机回传过来，被当成对方开口把自己打断。遇到这种情况把「允许打断」关掉：机器人想和说的时候对方的声音整段丢掉，不会再打断自己，代价是插不上话。
- **不能重启 QQ**：重启 QQ 进程会掉登录，要重新扫码。agent 从不碰 QQ 进程；Linux QQ 也不认 `--remote-debugging-port`，没法走 DevTools 读界面。
- **靠界面和日志**：认来电靠 OCR「邀请你」，接通靠「QQ 开始采集麦克风」，对方 QQ 号靠 SnowLuma 的一行警告日志。QQ 或 SnowLuma 升级改了其中任何一样都会失效；失效时插件只会不接或立刻挂断，不会接错人。
- **一个容器只有一通**：QQ 同一时间只能有一个通话窗口。
