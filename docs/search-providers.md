# 搜索提供商配置

搜索服务的地址与密钥在「提供商 → 搜索提供商」统一管理，按「API 搜索」和「浏览器搜索」分组展示。每台机器人在机器人页「联网搜索」单独设置是否允许搜索、来源优先级（按列表顺序 / API 优先 / 浏览器优先）、首选与后备来源（拖动手柄排序）、结果数量、超时、来源保留和回复链接策略，点击「保存配置」生效。不再有全局搜索配置。内置搜索插件仍承载工具执行与配置存储，其「配置搜索」按钮直接进入统一管理页，无需重复填配置。

## 管理列表

新建时先选服务：Exa、Tavily、Brave Search、Perplexity、TinyFish、Google / Bing（浏览器）会自动填好地址、工具名和参数名，自定义 HTTP API 与自定义搜索 MCP 再手动补充接入细节。列表每行：

- 勾选框直接启停并立即保存；停用后，正在使用它的机器人会跳过它并按后备继续。
- 测试按钮用已保存的配置（含已存密钥）搜索「Diana」一次，结果、耗时和 HTTP 状态显示在该行。
- 克隆会复制接入设置但不复制密钥，保存前需重新填写。
- Tavily、Brave、Perplexity、TinyFish 以及需要认证的 HTTP 接口未配置密钥时显示「待配置密钥」，机器人选到它们时也会提示。

## 接入方式

| 协议 | 可配置内容 | 约定 |
| --- | --- | --- |
| Exa MCP | 地址、工具名、API Key | 使用 Exa 的 query / numResults 参数；默认公共 MCP 无需密钥 |
| Tavily API | 地址、API Key | 兼容 Tavily 搜索请求与 results 响应；需要密钥 |
| 自定义 HTTP API | 完整接口地址、GET/POST、认证、参数名、固定 JSON 参数、结果字段映射 | 接收 JSON 响应，归一化为标题、链接、摘要；无需改成 MCP |
| 自定义搜索 MCP | 地址、工具名、搜索词参数、结果数量参数、API Key | 使用 HTTP MCP，支持 JSON 或 SSE 响应；数量参数留空时不传 |
| 浏览器搜索 | 搜索页面地址（可含 `{query}`）、搜索词参数 | 用服务器上的隔离 Chrome / Chromium 读取页面并提取结果链接 |

自定义 MCP 例如工具 `lookup_news` 接收 `search_text` 和 `limit`，就在工具名、搜索词参数、结果数量参数三个字段分别填写这些名称。搜索服务需要鉴权时填写 API Key，MCP 请求携带 Bearer 和 x-api-key；Tavily 请求使用 Bearer。接入地址支持 HTTPS，或 localhost / 127.0.0.1 / ::1 的本机 HTTP 服务，不接受在 URL 用户信息中嵌入凭据。

Exa 公共 MCP 和浏览器搜索无需 API Key，Tavily 需要账户密钥并可使用服务商提供的免费额度，具体额度以账户为准。更换为自己的兼容地址时按该服务要求填写凭据，已有免费入口和旧密钥继续沿用。

浏览器方式需要在 Diana 所在服务器安装 Chrome / Chromium，使用一次性隔离配置，不读取个人浏览器登录状态。没有可提取的结果链接、触发验证或渲染失败时，会按顺序尝试后备来源。

## 自定义 HTTP API

新建提供商后选择「自定义 HTTP API」，填写完整搜索接口地址。默认 POST 发送 JSON `{"query":"搜索词","count":5}`，也可选 GET，将同样参数放在 URL 查询字符串中。原地址已有查询参数会保留，搜索词和数量由运行时覆盖。「高级设置」中可以更换参数名，数量参数留空则不传。

认证支持无需认证、`Authorization: Bearer <API Key>` 和自定义密钥请求头（例如 `X-Search-Token: <API Key>`）。要求请求体携带密钥的服务，可在固定 JSON 参数中写 `{"api_key":"{api_key}"}`；真实密钥仍填在 API Key 输入框，不写进普通参数存档。固定参数支持嵌套 JSON，GET 下非字符串值编码为 JSON 字符串。HTTP 接口不会自动跟随重定向，请填写最终接口地址。

默认响应支持以下两种结构，链接自动识别 `url` / `link`，摘要自动识别 `snippet` / `content` / `description`：

```json
[{"title":"标题","link":"https://example.org/page","snippet":"摘要"}]
```

```json
{"results":[{"title":"标题","url":"https://example.org/page","content":"摘要"}]}
```

其他结构可以映射，例如响应为 `{"data":{"items":[{"page":{"href":"https://example.org/page","name":"标题"},"summaries":["摘要"]}]}}`，填写列表路径 `data.items`、链接字段 `page.href`、标题字段 `page.name`、摘要字段 `summaries.0`。路径只读取字段和数组下标，不执行脚本或 JSONPath 表达式。无效链接会跳过，重复链接去重，结果数量遵守机器人上限；空结果、结构错误、非 JSON、HTTP 错误和超时继续使用后备来源。

## 手动测试

编辑窗口的「测试搜索」读取当前未保存草稿，可沿用已存密钥；勾选清除密钥则测试也不再使用它。测试只执行当前提供商一次，不保存、不更换机器人路由，也不触发后备搜索。结果显示耗时、HTTP 状态（浏览器方式没有该项）、解析后的结果数量和内容。修改草稿后旧测试结果会清除。

测试会由服务端直接请求草稿里填写的地址，包括内网和本机地址，不做拦截；这和 WebUI 管理员本就拥有的权限一致。请求不跟随重定向，避免把密钥转发给别的服务。

## 路由与兼容

机器人的搜索配置只决定开关、来源顺序和参数，提供商目录和密钥仍取统一管理页。「API 优先」将 API 来源排在浏览器来源前；「浏览器优先」相反；同类内部保持列表顺序。

首次部署、什么都没填时，联网搜索默认开启：「浏览器优先」，依次试 Google、Bing、DuckDuckGo 浏览器搜索（需服务器装有 Chrome / Chromium），都失败或没有结果时用免密钥的 Exa 公共 MCP 兜底，无需任何密钥即可用；第一次保存任何搜索设置时这套默认路由会写入存档，不会丢掉 Exa 兜底。机器人页会标「默认配置」并展示这些值。只要存过任何旧搜索设置（如搜索方式、引擎顺序、Exa/Tavily 设置），就按原有配置走，不套用首装默认。

升级后，还没在机器人页保存过搜索配置的机器人沿用升级前全局搜索的开关、来源和参数，行为不变；保存一次后即完全按该机器人自己的配置运行，不再受旧全局开关影响。旧版本残留在机器人配置里的 `web_search` 字段继续忽略，新配置存于 `web_search_override` 字段，升级不会让旧值突然生效。

浏览器方式填写 Google、Bing、DuckDuckGo（以及旧配置里的百度）的标准搜索地址时，会按内置引擎处理，获得时间范围筛选和该引擎的人机验证识别；其他地址按自定义搜索页处理。

首选来源失败、超时或没有结果时按顺序补充后备；等待 4 秒仍未返回时启动下一个来源，每条后备队列同时最多运行两个来源，先取得有效来源的结果会取消其余请求。慢请求可能增加来源调用量，全部调用仍计入预算并共享总超时。搜索浏览器复用 Chrome 进程，每次使用独立隐身上下文，空闲 3 分钟后退出；无法复用时退回一次性浏览器。搜索路由最多 16 个来源，同一来源不重复选择。搜索使用主备回退；模型的轮询与加权轮询仍在各模型用途中设置。

升级后，未修改搜索路由的机器人继续沿用已有插件启用状态及浏览器搜索引擎顺序、Exa/Tavily 设置；旧密钥无需重填。保存任意搜索提供商时，会将旧密钥迁移进统一凭据存档。已存密钥不回显，编辑时留空沿用，单独勾选清除后保存才删除。原内置 Tavily 的 `TAVILY_API_KEY` 环境变量回落继续生效，新建自定义来源不会继承该环境密钥。

关闭搜索会保留已选来源，仍可调整。仍被任一机器人使用的提供商（含沿用升级前全局路由的机器人）不能删除，需先在机器人页更换来源并保存；已停用提供商不可用于保存新的启用路由。群级搜索开关和参数覆盖已不再生效，旧存档中的值会被忽略。
