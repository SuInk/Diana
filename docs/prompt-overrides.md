# 内置提示词覆盖

代码里写死的提示词都登记成一条：标题、什么时候发给模型、默认原文、可用的占位符。它们属于机器人，在 WebUI「机器人 → 高级 → 内置提示词」里逐段改。改过的正文保存后生效；没改过的每次升级都跟着新版默认文案走。

提示词不跟着人设走：人设就是一份 [SOUL.md](soul-md.md)，只回答「她是谁」。换人设不会动提示词覆盖，改提示词也不会改人设。

演示站没有后端，提示词目录是 `frontend-next/src/demo-prompt-catalog.json`，和登记表逐字相同，由 `webui/demo_prompt_catalog_test.go` 生成并校验（登记表一变测试就失败，按提示重新生成）。

## 导出和导入：一份 YAML

卡片标题栏的「导出」把全部内置提示词写成一个 YAML 文件（`diana-prompts-日期.yml`）：顶上是 `format_version` 和导出时的 `diana_version`，`prompts` 下按分组列出每一段，改过的写改过的正文，没改过的写当前默认原文，每段上面一行标题（带占位符），分组前一条横幅。带输出格式的条目紧跟一条 `<键>.format`。

写成 YAML 而不是 JSON：两百多段提示词大多几百字、带换行，YAML 的字面块（`|-`）能原样写，还能挂注释；JSON 只能写成一行塞满 `\n` 的字符串，没法手改。

「导入」读回这样一份文件，填进编辑器，保存配置才生效。「编辑」在页面里直接摊开同一份内容，改完点「应用」，效果和导入一样。导入是整份替换，读法宽松：

- 没写的段落用默认值，和默认原文一样的不存成覆盖。
- 这一版登记表里没有的键（拼错的、旧版本删掉的）跳过，界面上列出来，不会整份拒收。所以旧版本导出的文件能导进新版本，新增的段落自然用默认值。
- 缺 `format_version`、版本号比当前 Diana 新、YAML 缩进写错（报第几行），直接报错。

接口是 `POST /api/assistant/prompts/export`（请求体带编辑器里当前的覆盖表，没保存的改动也算）和 `/prompts/import`（只解析不保存），实现在 `model/assistant/prompt_file.go`。

## 存储：只存改过的

机器人配置里原来那 8 个整段提示词字段（`prompt_chinese_slang_text` 等）已经删掉，不做迁移；这些内容现在只在 `prompt_overrides` 里。

机器人配置的 `prompt_overrides` 键是提示词的登记键（如 `reply.wake_only`），值是正文。保存时会做三件事：

- 和默认值相同的值直接丢掉。界面上把正文改回原样再保存，不该留下一条把当前默认文案冻结住的覆盖。
- 空值丢掉，`\r\n` 统一成 `\n`。
- 登记表里不认识的键丢掉（旧版本删掉的提示词）。

单段上限 20000 字（`PromptOverrideMaxRunes`），只挡误粘贴，不是建议长度：提示词每轮都要发，写得越长每轮越贵。

没有群级覆盖：同一台机器人的所有群用同一套提示词。群里要补充语境用「补充判据」和群自己的 SOUL.md。

## 输出格式

接话评分、发送前审核、各种分类器的输出要被程序解析。这类提示词的输出格式单独成一栏（`contract`，覆盖键是 `<键>.format`），运行时永远拼在正文之后。格式也能改，但单独放、带警告：正文随便改；格式改坏一个字，这些链路解析失败的兜底是沉默或放行，用户只会看到「机器人突然不说话了」。分开放，改判据的人不会顺手把格式也改了。

界面上格式改过的条目标「格式已改」；恢复默认会把正文和格式一起恢复。

「什么情况下愿意接话」（`routing.participation.willingness`）另外摆在「行为 → 接话」里就地改：按「愿意接 / 可以接一句 / 不接」三栏写大白话，下一段 `routing.participation.willingness_scale` 把三栏换成闲聊分（愿意接 0.70–0.95、可以接一句 0.40–0.60、不接 0.10–0.30），闲聊档位照这个分数决定开不开口。它取代了原来带分数的「闲聊分锚点」，旧的锚点覆盖不再生效。评分模型和判断模型读的是同一段。

接话评分里原来写死的骨架也都能改：开头的开关与档位（`{relevance}`、`{chat_level}`）、任务说明、两项字段的含义、愿意程度换成闲聊分的那句、输出格式、解析失败后的重问提醒，以及补充判据的段头和收尾。绑定判断模型时，它按程序里固定的六档作答，「什么情况下愿意接话」和换算那句写进它的题目说明。

## 占位符

带运行时信息的提示词（当前时间、发言者、字数上限等）用 `{name}` 占位，界面列出可用的名字。只替换登记过的名字，正文里别的花括号原样保留，写 JSON 示例不会被吃掉。删掉占位符不报错，只是那项信息不再进提示词，界面会提示。

## 不在范围内

- Agent 运行协议（`model/agent` 的系统提示词、循环控制和修复提示）与各工具的 `Description()`。
- WebUI 里「用 AI 生成人设」和「检查写法」用的提示词：它们不属于任何一台机器人，没法按机器人覆盖。
- 纯结构性的段头和标记（如 `【当前需要回复的消息】`、分条标记）：代码和测试按它们解析，改了会坏。
- 历史来源图片失效的三句运行时提示（`imageContextNotice` 和同轮补充里的【图片读取提示】）：只报告事实，暂未登记。
- SOUL.md、补充判据、账号安全规则这些本来就有输入框的内容，仍在原来的位置编辑。
