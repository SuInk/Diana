# 内置提示词覆盖

代码里写死的提示词都登记成一条：标题、什么时候发给模型、默认原文、可用的占位符。它们属于人设，在 WebUI「机器人 → 人设」页最下面的「内置提示词」里逐段改，或者点人设卡片右上角的「YAML」整份编辑。改过的正文保存后生效；没改过的每次升级都跟着新版默认文案走。

## 跟着人设走

提示词和人设正文、品格、自称一样，是「这个角色怎么说话」的一部分：

- 存进人设库时一起存（人设的 `prompts`，同样只存改过的）。
- 从人设库套用一套人设时，机器人的提示词覆盖整份换成那套的；人设没带提示词就是全部用默认值，不和上一套混在一起。
- 在当前人设上改了提示词，人设选择就变成「自定义」，和改正文一样。
- 运行时读的仍是机器人配置里的 `prompt_overrides`：人设库是套用来源，不是活绑定（见 [personas.md](personas.md)）。

## 人设 YAML：全部提示词配置

一套人设的 YAML 就是它的全部提示词配置：正文、品格、自称与语气词、开关，以及 `prompts` 下登记表里的**每一段**提示词。改过的写改过的正文，没改过的写默认原文，注释里写着标题、用途、占位符和是否锁了输出格式。

读回 YAML（编辑器「应用」、人设库导入）时 `prompts` 必须一段不少、一段不多：

- 少了一段 → 报错并列出缺的键，不会悄悄回落默认值。
- 多了不认识的键（拼错、旧版本删掉的）→ 报错，不会被静默丢掉。
- 和默认原文相同的正文不存成覆盖。

编辑器里「应用」是整份替换：YAML 里没写的品格、正文就是没有，不保留表单里原来的值。应用后仍要按「保存配置」。

没有 `prompts` 这一节的文件（这个功能之前导出的人设、手写的最小人设、角色卡）照样能导入，按全部默认值处理：它们从来没声明过提示词，谈不上缺了哪段。

YAML 只在后端生成和解析（`POST /api/assistant/personas/yaml`、`/personas/parse`），前端没有 YAML 库。

## 分享

编辑器里「复制」「下载」，或者在人设库里导出单套 / 整库，拿到的都是同一种 YAML 文件；对方在人设库里导入即可。导出的文件不带 ID 和时间戳：ID 是本机的，导入时一律重新分配。以前的 JSON 导出连品格都没带，现在是完整的一套。

## 存储：只存改过的

机器人配置的 `prompt_overrides` 和人设的 `prompts` 形状相同，键是提示词的登记键（如 `reply.wake_only`），值是正文。保存时会做三件事：

- 和默认值相同的值直接丢掉。界面上把正文改回原样再保存，不该留下一条把当前默认文案冻结住的覆盖。
- 空值丢掉，`\r\n` 统一成 `\n`。
- 登记表里不认识的键丢掉（旧版本删掉的提示词）。这只是存储层的清洗；读 YAML 时不认识的键直接报错。

单段上限 20000 字（`PromptOverrideMaxRunes`），只挡误粘贴，不是建议长度：提示词每轮都要发，写得越长每轮越贵。

没有群级覆盖：同一台机器人的所有群用同一套提示词。群里要补充语境用「补充判据」和群级人设。

## 锁定的输出格式

接话评分、发送前审核、各种分类器的输出要被程序解析。这类提示词把输出格式拆成锁定段（`contract`），界面上只读，运行时永远拼在正文之后。正文随便改；格式要是能改，改坏一个字的后果是解析失败，而这些链路解析失败的兜底是沉默或放行，用户只会看到「机器人突然不说话了」。

格式说明和正文交织、没法干净切出尾部的少数几段没有锁定段，用途说明里会写明「改动时保持字段名和 JSON 结构不变」。

## 占位符

带运行时信息的提示词（当前时间、发言者、字数上限等）用 `{name}` 占位，界面列出可用的名字。只替换登记过的名字，正文里别的花括号原样保留，写 JSON 示例不会被吃掉。删掉占位符不报错，只是那项信息不再进提示词，界面会提示。

## 旧字段的迁移

`prompt_chinese_slang_text`、`prompt_plaintext_rules_text`、`prompt_time_template`、`prompt_group_sender_template`、`prompt_image_only_text`、`prompt_wake_only_text`、`proactive_reply_prompt`、`proactive_reply_router_prompt` 早于覆盖表。以前 `WithDefaults` 会把当时的默认值写进这几个字段，前端保存时原样带回，于是库里存的多半是某一版默认值的化石：默认文案后来改了，存量机器人还跑着旧版。

现在读配置时：

- 字段内容等于当前默认值，或等于 git 历史里任何一版默认值（Go 常量和前端副本都算，按 SHA-256 前 16 位比对）→ 认作化石，丢掉，这台机器人回到当前默认文案。
- 其余内容认作用户所写，搬进 `prompt_overrides` 对应的键；覆盖表里已有这个键时以覆盖表为准。
- 旧字段随后清空，不再写入默认值，所以不会再长出新的化石，那张历史哈希表也不用再维护。

旧客户端仍按旧字段提交也能生效，内容会在保存时迁进覆盖表。「人设 → 恢复内置默认」会一并清掉这八个键的覆盖，效果和迁移前一样。

## 不在范围内

- Agent 运行协议（`model/agent` 的系统提示词、循环控制和修复提示）与各工具的 `Description()`。
- WebUI 里「用 AI 生成人设」和「检查写法」用的提示词：它们不属于任何一台机器人，没法按机器人覆盖。
- 纯结构性的段头和标记（如 `【当前需要回复的消息】`、分条标记）：代码和测试按它们解析，改了会坏。
- 历史来源图片失效的三句运行时提示（`imageContextNotice` 和同轮补充里的【图片读取提示】）：只报告事实，暂未登记。
- 人设正文、品格、补充判据、账号安全规则这些本来就有输入框的内容，仍在原来的位置编辑。
