Diana 多平台 AI 助手

用一个安静、可管理的 Web 控制台连接 QQ 与 Telegram，将对话模型、视觉模型、图片生成、长期记忆、联网搜索和自动化任务组合成可持续运行的助手服务。

核心能力

从接入到运维都在同一套边界内

多通道同时在线

QQ OneBot V11 与 Telegram Bot API 可同时运行；回复、图片和提醒始终回到消息来源通道。

模型职责拆分

对话、识图、意图识别和图片生成可以分别绑定 Provider 与模型，未绑定时按明确规则回退。

内置联网能力

联网搜索属于内置能力，不依赖用户安装插件；Agent 可按问题时效性决定是否检索后回答。

群级回复策略

每个群可独立配置触发词、人设、回复时间、屏蔽 QQ 号、群等级门槛和插件覆盖。

长期记忆与检索

近期上下文、结构化事实、用户关系画像和压缩摘要分层保存，可选择是否跨群共享非敏感记忆。

可解释的处理记录

事件明细记录回复与不回复原因、模型用量和最终结果；调试模式进一步呈现上下文与工具调用链。

快速开始

五分钟启动一个可登录的控制台

  1. 1

    下载完整包

    从最新 Release 选择与你的系统和架构一致的 `.tar.gz` 或 `.zip`，不要给普通部署只下载裸二进制。

  2. 2

    校验 SHA-256

    下载同一 Release 的 SHA256SUMS，确认归档在传输过程中没有损坏或被替换。

  3. 3

    运行启动脚本

    Linux/macOS 执行 ./run.sh，Windows 执行 run.bat。

  4. 4

    登录 WebUI

    打开 http://127.0.0.1:18080，使用首次启动日志中生成的管理员账号和密码。

  5. 5

    配置模型与通道

    先保存 LLM 配置并执行测试，再添加 QQ 或 Telegram 机器人并启动。

部署

选择与你维护方式匹配的安装形态

完整 Release 包适合直接运行；Docker 适合容器运维；源码部署适合开发和深度定制。

推荐

归档已经包含后端、启动脚本和 frontend-next/dist，目标机器不需要 Go、Node.js 或 npm。

1. 下载与校验

# Linux
sha256sum -c SHA256SUMS --ignore-missing

# macOS
shasum -a 256 diana-webui-darwin-arm64.tar.gz

# Windows PowerShell
Get-FileHash .\diana-webui-windows-amd64.zip -Algorithm SHA256

2. 解压并启动

# Linux / macOS
tar -xzf diana-webui-darwin-arm64.tar.gz
cd diana-webui-darwin-arm64
chmod +x run.sh
./run.sh

# Windows
Expand-Archive .\diana-webui-windows-amd64.zip
.\diana-webui-windows-amd64\run.bat

Apple Silicon 使用 darwin-arm64，Intel Mac 使用 darwin-amd64。首次启动前可设置 DIANA_ADMIN_PASSWORD 固定管理员密码。

首次配置

先保证访问安全，再连接外部服务

管理员凭据

未设置环境变量时，首次启动会随机生成 diana# 开头的账号和安全密码，仅在该次启动日志显示一次。之后以 SQLite 中的凭据为准。

DIANA_ADMIN_USERNAME=diana#operator
DIANA_ADMIN_PASSWORD=replace-with-a-long-password

公网访问

Diana 默认适合本机或内网访问。暴露到公网时应在前面放置 HTTPS 反向代理，并限制管理端来源；OneBot 连接同时配置 access token。

# Nginx 核心代理头
proxy_set_header Host $host;
proxy_set_header X-Forwarded-Proto $scheme;
proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
不要提交密钥

runtime.env、.env、模型 API Key、Telegram Bot Token 和平台 Cookie 都不应进入 Git。

多机器人上下文

每个机器人配置独立保存平台、账号、主人、人设、触发规则和模型分配。默认按配置隔离会话与记忆；关闭隔离后仍保持发送通道路由，不会把 QQ 回复误发到 Telegram。

模型配置

Provider 管连接，角色分配管职责

Diana 支持 openai_compatible、gemini 和 anthropic。一个 Provider 配置可以同步模型列表；机器人再为不同职责选择具体模型。

角色用途未分配时测试重点
对话最终回复、Agent 推理使用激活 LLM 配置中文表达、工具调用、长上下文
识图普通图片、截图、历史图片描述跟随对话模型小字 OCR、界面结构、多图关系
意图识别主动回复、回复抑制、关系评估跟随对话模型速度、稳定 JSON、低成本
图片生成文生图与图片编辑使用对话 Provider 的生图配置必须实际生成图片验证

上下文预算

每次请求会为输出预留 token，再按系统指令、工具证据、当前消息、摘要和历史消息的优先级裁剪。图片也占用视觉 token；多图和 high/original 清晰度应配合更大的上下文上限。

LLM_CONTEXT_WINDOW_TOKENS=65536
LLM_MAX_CONTEXT_TOKENS=65536
LLM_MAX_OUTPUT_TOKENS=2048
LLM_TIMEOUT_MS=60000

群聊策略

每个群都可以拥有独立行为

启用状态单独停止某个群，不影响其他群和私聊。
触发与主动回复触发词负责确定性唤醒；被动语义路由判断普通群聊是否值得回复。
回复时间支持同日和跨夜时间段、IANA 时区、主人绕过和静默期提示。
屏蔽 QQ 号群级名单只影响对应群，不影响同一用户在其他群或私聊中的消息。
人设与上下文群级系统提示词、历史条数和回复长度可以覆盖机器人默认值。
插件覆盖每个群可跟随全局、强制开启或强制关闭具体插件。

Agent 与工具

模型只有在权限与场景允许时才能行动

Agent 循环由模型选择工具，运行器执行后把结构化结果送回模型，直到生成最终回复或达到步数上限。工具注册表按平台、关系权限、群配置和插件状态收敛，不把所有能力无条件暴露给每条消息。

内置联网搜索

时效性、事实核验和陌生实体问题可先搜索再回答；这是内置工具，不提供安装或卸载入口。

提醒与订阅

一次性提醒和周期任务持久化到 SQLite，后台调度后由来源通道发送。

MCP 与 Skills

按配置加载外部 MCP server 和技能目录，支持启停与扩展发现，并受工作目录和命令白名单限制。

图片工具

识别、生成和编辑分开授权；生图请求必须走真实图片结果测试。

调用链

一条消息如何决定回复或忽略

  1. 接收与归一化

    平台 adapter 把文本、@、引用、图片、文件和发送者信息转换成统一 MessageEvent。

  2. 补全与缓存

    解析引用、转发和媒体引用；短效平台图片尽量写入本地历史媒体缓存。

  3. 确定性门禁

    检查机器人/群启用状态、群白名单、屏蔽用户、回复时间、群等级和回复抑制。

  4. 触发判断

    私聊直接处理；群聊依次识别显式 @、引用、触发词和插件命令。显式 @ 优先于引用语义。

  5. 被动语义路由

    未直接触发的群聊可交给轻量意图模型判断是否指向机器人、是否值得主动加入。

  6. 上下文组装

    组合系统提示、用户关系、长期记忆、近期历史、图片和工具证据，并按 token 预算裁剪。

  7. 模型与工具循环

    按消息内容选择对话或识图角色；Agent 模式下执行受限工具并持续记录调用步骤。

  8. 发送与审计

    格式化、分段或转发发送到来源通道，持久化回复结果、耗时、token 和决策原因。

记忆

短期上下文与长期事实分层处理

01

近期上下文

保留当前会话最近消息，优先满足引用、追问和连续对话。

02

压缩摘要

历史增长到阈值后提炼会话摘要，减少重复 token，同时保留主题和未完成事项。

03

结构化长期记忆

异步提取稳定事实、偏好与关系信息，避免每轮请求都携带全部原始聊天。

04

按需检索

历史工具按时间、关键词、用户和群范围搜索；跨群检索默认关闭，可按机器人配置启用。

隐私边界

跨群记忆开启后仍应只检索适合共享的非敏感事实。平台上下文隔离与跨群检索是两个独立开关。

多模态

原图、OCR 与历史描述各司其职

平台媒体引用→下载与类型校验→本地原图缓存→视觉模型 / OCR→回答与可复用描述
  • 普通聊天图片转成 Provider 可用的 data URL，不在媒体层主动缩放原图。
  • 文档页渲染后走高精度 OCR 提示，表格、页码和脚注尽量保留。
  • 历史图片按内容 SHA-256 缓存客观描述；缓存版本变化时应重新计算。
  • 单次请求限制图片数量，并将图片开销纳入 token 预算，防止 base64 历史无限增长。
  • 视频提取有限数量的上下文帧，临时帧处理完成后清理。

数据与安全

一个 SQLite 主库，加上可清理的媒体缓存

数据默认位置备份要求
配置、管理员凭据、会话、消息、记忆、任务data/diana.db必须备份；更新前应复制主库，并保留 WAL/SHM 一致性。
入站媒体缓存data/media可按容量淘汰；历史识图依赖时建议随数据备份。
历史媒体DIANA_HISTORY_MEDIA_DIR 或系统缓存目录长期历史回看需要；可单独设置持久目录。
运行日志logs/diana.log按运维策略轮转；不要公开包含平台事件的日志。
更新备份.diana-updates保留最近可回滚版本和更新结果。

安全模型

WebUI 使用登录会话保护 API；OneBot 使用独立 access token；外部 URL 下载经过网络边界检查；Agent 命令受工作目录、允许列表和超时限制。调试模式可能记录完整模型上下文与工具参数，只应在可信环境短期开启。

更新

发现更新与执行更新是两件事

控制台只显示新版本提示点，不会自动安装。管理员点击并确认后，才根据部署形态执行对应更新流程。

完整 Release 包

下载匹配系统架构的完整包与 SHA256SUMS，校验、暂存、备份数据库和旧版本、切换、启动并请求 /api/health；失败自动恢复。

Docker

由镜像与编排系统更新，不在运行中的容器内替换二进制。先确认数据卷，再拉取或重建镜像。

源码 checkout

使用 Git 更新源码，重新执行前端构建与 Go 编译。工作区有未提交修改时必须先处理冲突。

旧版本边界

如果当前运行版本尚未包含 Release 自更新器，第一次升级仍需手工下载完整包、校验、备份并切换；仅出现按钮不能替代后端能力。

故障排查

先从事件明细和调用链定位

机器人在线，但群里不回复

检查事件明细中的决策原因，再依次核对：群是否启用、回复时间、屏蔽 QQ 号、群等级门槛、显式 @ 是否识别、触发词、被动回复阈值和回复抑制状态。

引用机器人消息并 @，却被当成普通引用

运行版本需要包含“显式 @ 优先于引用”的修复。事件中应看到 to_me=true，后端首先检查 at segment，再进入引用语义判断。

视觉模型看不清截图或小字

为“识图”单独绑定已验证的视觉模型；提高上下文上限；截图使用高细节；文本密集图片采用 OCR + 原图双通道，并确认图片没有被数量或 token 预算裁掉。

群管理显示 not found 或看不到已加入群

确认 OneBot 已连接，并验证 get_group_list 可用。连接不可用时页面只能展示 SQLite 中已经保存的群配置。

Telegram 无法发送本地图片

Telegram 不能拉取只对本机开放的媒体 URL，Diana 会改为 multipart 上传。确认 Bot API 地址、代理、文件大小限制和本地文件读取权限。

更新后健康检查失败

查看 .diana-updates 中的最近结果与备份，检查端口冲突、前端目录、数据库权限和新二进制架构。Release 更新 helper 会在探活失败时尝试恢复旧版本。
