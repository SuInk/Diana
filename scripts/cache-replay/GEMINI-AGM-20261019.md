# Gemini 经 AGM 的独立验证（2026-10-19）

使用用户授权的 Yuki 生产 Gemini 连接凭据，测试 Diana `04a7f0a1`。网关为 AGM `4.9.7-beta.10`，部署 revision `e5f92c2dbc5d63da5e6dbd865706e882ed8363de`；请求模型 `gemini-3.8-flash`、思考强度 `MEDIUM`，实际响应的 `modelVersion` 为 `gemini-3.8-flash-n`。密钥、管理员凭据、账号标识和原始 trace 不提交。

Yuki 当前生产主路由使用 AGM 的 Chat Completions 协议。本次完整 Diana 对话和后缀对照使用 Diana 的原生 Gemini 适配器及 AGM 的 `/v1beta` 接口；同一网关和凭据不代表相同协议或最终上游请求。这里的缓存数据均为 AGM 返回值，不能称为 Google 官方直连结果。

## 统计边界

- 原生 `usageMetadata.cachedContentTokenCount` 只有明确出现、值有效时才计作已知；缺失为未知，不填零。已知样本用 `Σcached / Σprompt`，另外报告未知请求数及输入量，不能拿已知子集百分比代表整体。
- 当前部署的 AGM 已区分缺失、明确零及正值，native collector 保留上游字段。Diana 的 `Usage.CachedInputTokens` 仍是整数，无法独自保留这三种状态，因此以 HTTP wire 的字段存在性为准，不能从控制台的零反推原始零命中。
- AGM 的 `countTokens` 在凭据、网络或上游失败时可能降级到本地估算，部分回退无可靠标记。本次没有调用它，也没有将本地字符估算当作 Gemini tokenizer。
- 同时存在正常生产请求，网关账号调度、服务端缓存驻留和适配变换未完全控制。没有为实验修改 Yuki 或 AGM 服务配置。

## 后缀对照

两臂各做 A1、A2、B1、B2，共 8 次非流式 `generateContent`。A1/A2 请求字节相同，B1/B2 字节相同；每臂 A/B 仅最后一条用户文本变化，首次不同在该文本索引 8。32 条历史、系统指令、工具、工具选择及生成参数完全相同。两臂使用独立随机前缀，避免互相预热。

共享文本按字符除以四粗估约 20,261，短后缀约 1,037、长后缀约 4,037。这些只是文本规模标签，不能证明实际后缀短于 Google 的某个 token 阈值。下面的输入与缓存量取自真实响应 usage。

| 条件 | 请求 | 输入 token | 缓存 token | 已知样本命中率 |
| --- | --- | ---: | ---: | ---: |
| 短后缀 | A1 | 23,865 | 未返回，未知 | — |

8 次均 HTTP 200、正常回复 `OK`，无重试、429 或工具执行。其中 5 次缓存字段已知，3 次未知；已知子集输入 126,221、缓存 78,128，加权 61.90%，这不是全部 8 次的确定命中率。

精确重复中观测到 2,036～2,038 token 的未缓存缺口，但短后缀 B1 仍退回约 4.6k 的静态头部量级，长后缀 B2 连缓存字段也没有返回。因此，这批数据没有建立“尾部低于约 2k 就能命中历史”的充分条件，也不能证明内部只有两个缓存检查点。它支持继续精简冗余，同时要求按实际路由和完整请求观察，而不是把 [Issue #1140：Gemini 隐式缓存后缀实验](https://github.com/SuInk/Diana/issues/1140)中的机制假说写成裁剪门禁。

152 个成功响应均返回输入和输出用量，与 Runtime 逐项对齐；全部返回 `gemini-3.8-flash-n`。另有一次记录器到上游的传输错误产生本地 HTTP 502，该请求没有 usage，最终入站没有失败或取消。没有 429。后台产生 2 条记忆、1 条笔记和 2 个群历史快照。完整后缀是对 native 请求中文本部分进行布局转换后的 Diana 本地估算，不含媒体或完整协议开销，不能当成 Google token 数。

只有 4 / 27 个首步报告缓存字段，对应已知子集命中率 78.804%；其余 23 个未知。工具续接中 12 / 28 个字段已知，对应子集 85.927%，另 16 个未知。记忆提取、关系评估、发送审计的缓存字段均缺失。不能将这些选择性覆盖的百分比与 DeepSeek 的全字段覆盖结果直接横比。

只利用未知缓存量介于零与对应输入量之间这一约束，全体命中率的数学上下界是 21.217%～96.003%。它不是置信区间，更不是实际点估计；136 个未知请求使我们无法据此判断整体是否达到 95%。已知子集 84.148% 同样不能改称总体命中率。

逐条核对 27 条回答、工具与存储回执：本次身份、跨群、引用作者、80W/Type-C/温升及最后短答的关键事实正确；第 11 轮明确要求查询 `chat_history`，模型没有调用，属于工具遵循失败，尽管回答内容可由当前历史支持。第 23 轮更新同一笔记并保留原触发词，第 27 轮实际记忆查询非空，第 38 轮实际读取 Skill 并查询历史，第 41 轮没有因旧点名重复读取 Skill。

第 41 轮额外提出测量仪器和安全检查建议，不能把这些写成群里已经约定的事实或标准。26 次普通模拟出站没有发现内部标记泄漏，另有 1 张转发卡片；这不构成真实 QQ 客户端卡片渲染验收。没有把零失败事件或关键字齐全当作质量全面通过。

### 实际发现的前缀分叉

首步的系统指令与工具并非对所有权限类别共用一份：

- 14 个群管理权限首步共用一套稳定工具定义；其中 `platform` 有 17 个 operation。
- 7 个普通成员首步共用另一套稳定定义；`platform` 仅 5 个 operation，并减少相应参数。
- 6 个机器人主人首步使用第三套稳定定义，另有主人专属 `github` 工具。主人与成员的 Agent 头部还包含不同步数额度。

组内没有发现随机的 required、enum 或函数顺序变动；跨组差异来自现有权限展示逻辑。源码位于 `model/assistant/platform_interface_tool.go` 的 `newDianaPlatformTool` / `InputSchema` 和回复工具注册表，执行时仍在 `platform_moderation_auth.go` 核验真实权限。群里交替发言即使属于同一会话，也可能因此在历史之前分叉。

所以本 PR 的稳定性应限定为同一权限类别、注册表和模式下，不因本轮延迟加载而重写原生定义。后续可以评估稳定工具分发入口、将当前额度等差异移到尾部，并保留执行时授权；本轮没有为命中率放开权限。删除动态资料能减轻负担，但尚未消除这些既有分叉。

## 同一 Diana 请求的流式与非流式诊断

从上述 Runtime 的第 1 个主回复请求取原生 Gemini JSON 内容，新增固定匿名会话头后，分别做流式 S1/S2 和非流式 N1/N2，共 4 次。四次发送字节哈希相同；原 Runtime 的原始 JSON 字节未单独留存，因此只保证内容复用和这四次之间的字节一致，不声称与原 wire 字节完全一致。

| 请求 | 模式 | 输入 token | 缓存 token |
| --- | --- | ---: | ---: |
| S1 | 流式 | 13,822 | 未返回，未知 |
| S2 | 流式精确重复 | 13,822 | 11,781（85.23%） |
| N1 | 非流式 | 13,822 | 11,781（85.23%） |
| N2 | 非流式精确重复 | 13,822 | 11,781（85.23%） |

四次均 HTTP 200，SSE 全帧解析与 usage 合并没有错误，S2 明确包含缓存字段。因此本轮不能将未知字段统一归因于流式不支持缓存或必然丢字段。三个已知响应的未缓存缺口均为 2,041；即使精确重复，这份 13,822 token 请求本次也只观测到 85.23%，不能把 95% 当作它应达到的固定标准。这不是对其他长度或模型缺口的保证。

四次响应的账号、会话标识经不可逆摘要比较均一致，不公开原标识；响应映射模型为 `gemini-3.8-flash-medium`，实际 `modelVersion` 仍为 `gemini-3.8-flash-n`。当前部署按 tenant、稳定会话头和内容锚点派生会话号，响应不会原样回显请求值。固定头属于本组新增条件，不能反推原 Runtime 的路由，也没有证据证明 AGM 内部最终上游 payload 完全相同。每次模型都返回一个工具调用、无正文；本组没有执行工具或续接，只作计量诊断。

## 可复现性与范围

完整对话使用公开的 [43 条合成集合](../../docs/testing/context-simplification.zh.json)，同样包含 4 人、2 群、交叉引用、真实工具续接、记忆、笔记和并发输入。Gemini 通道的记录与分析使用本机私有适配 helper；公开 `run.py` 目前仍要求直连 DeepSeek，没有把临时 Gemini helper 当作稳定公开功能。原始请求、响应、哈希、构建输入和逐条质量检查留在本机忽略目录。

本次不覆盖 Google 直连、Yuki 的生产 Chat 协议等价性、AGM 内部最终 payload 完全一致性或真实 QQ 投递。它不能验证长期 95% 命中率，也不替代回答质量验收。原 DeepSeek 对照与刷新后验证见[上下文精简报告](RESULTS-20261019.md)。

本轮隔离实例、模拟端和 SSH 转发桥均已停止，测试端口已释放；没有向日常机器人部署本 PR。
