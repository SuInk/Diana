# 上下文精简与 Runtime 回放验证（2026-10-19）

下列对照的基线为上游 `e092dce3`，候选实现为 `59b7bd11`。这是上游刷新前的历史回放；本 PR 后续 rebase 到 `3b83ac30` 并将合成身份改为五位测试号段，不把旧数据改称新版本的模型实测。本次优先删除重复注入和跨轮恢复状态，保留自动记忆召回；没有新增“每轮 3k token”的硬截断或门禁。

## 行为与兼容边界

- 删除“更早的图片索引”、重复的语义引用原文、图片描述提醒、最近搜索候选 URL 清单、自动能力自述、连续回复的旧答案预览、长期保存区目录、近期 @ 候选名单。
- 当前平台引用/提及关系只保留短事实并去重。当前发言者、账号权限、真实引用与语义来源仍分别处理，不把未知对象当作机器人。
- 删除结尾人设/深度锚点、隐式群聊长度与腔调、独立好感度分数及派生语气、心情语气扩展。真实学习到的风格笔记、群规则和 VRChat 表情状态继续保留。
- Skills 仅保留名称与用途；使用时 `read_skill`，长文用 `next_offset` 续读。旧的 Skill 常驻和关键词自动展开不再生效，关键词仍可用于发现。显式 `tools_load(Skill名)` 保留全文兼容；超限明确失败，不返回半份契约。
- 工具加载状态只在一次 `Runner.Run` 内有效，不再保存和回贴跨轮完整契约。原生工具定义仍稳定，本次 Run 内已加载的工具可继续使用。
- 显式 Skill 点名只识别当前用户原文，历史、引用和转发里的旧点名不会变成当前轮的强制读取要求。
- 联网调研的最新状态只为当前请求附加一次，普通规划和强制收尾均能读到；历史里不累计重复的调研提示。
- `chat_history` 能找回已发送正文中的链接，不返回浏览工具的历史参数。管理员可查已保存 trace；未保存的搜索候选需要重新检索。媒体记录和按需读取工具保留，远程资源实际过期时仍可能不可读取。

自动记忆的候选、排序、默认开关、预算和预取路径未改。核心画像、相关记忆、线程便签、自述、笔记本、世界书及跨群召回继续使用原路径。

## 滑动窗口

本次没有调整历史预算参数：近期历史默认 16,000 token，配置最高 32,000，同时受模型窗口 55% 限制；候选最多 4,096 条，最近 3 轮提高保留优先级。相关记忆上限 2,400、核心记忆 600、线程便签 1,200、自述 1,200，各自仍受原窗口份额限制。

最终请求还需扣除输出预留、工具定义及 128 token 安全余量。旧实现可能在这个阶段截掉当前要求的中间内容，或拆开工具调用与结果。本次修复将当前输入、显式当前补充和活动工具批次完整保留；显式分组与隐式 call/result 关联一起处理。连必要输入都放不下时，在发 HTTP 前明确报容量不足。WebUI 管理对话也在 Runner 入口固定当前用户要求，避免后续工具观察或强制收尾把它降成历史。

较老的可选历史仍会滑出窗口；非原子可选文本仍可能按既有预算裁剪。`AtomicText` 内容与工具批次不会在中间截断，极端超限时可选原子块可能整体让位。因此“自动记忆策略保留”不代表所有极端窗口下的最终 payload 逐字相同。

## DeepSeek 对照方法

两个版本分别编译，使用独立空白 SQLite、相同配置和直连 `deepseek-flash` Responses API，顺序执行同一套 43 条合成发言。包含 4 人、2 群、交叉回复、并发入站、主人/群主区别、真实工具续接、笔记读写、后台记忆提取、旧消息引用与条件纠正、点名 Skill 和回复详略切换。模型实际回复写入后续历史。

OneBot 对端仅监听回环地址并记录本地 ACK，不连接 QQ。后台任务等待最多 90 秒，`pending`、`running`、`processing` 都计入等待；结束时仍未完成的任务照实报告。没有把生产 QQ 流量用于本次对照。

缓存按原始 usage 的 `Σcached / Σinput` 统计，字段缺失单列未知。原始报文与 Runtime 用量按 token 三元组和时间关联；失败 HTTP、兼容降级和取消不算成功样本。首个回复、连续成员首步、主人首步、并发首步和工具续接分别统计。

### Gemini 后缀实验的启示

[Issue #1140：Gemini 隐式缓存后缀实验](https://github.com/SuInk/Diana/issues/1140)提示：仅把易变材料放在历史后面，不能保证隐式缓存命中历史；本地探针没有报告分叉，也不能当作供应商命中。该实验提出的“总长减约 1.7k～2k”仍是有限样本的机制假说，缓存字段不是公开的连续前缀结束位置；不据此添加固定门禁或裁剪用户原文。

上述 1,183 / 1,448 是更窄的补充范围；即使补齐为 1,380 / 1,688，仍是 Responses 文本经 Diana 估算器所得，不能直接与 Gemini 的实验阈值比较。Gemini 需对最终适配后的完整请求使用官方 `countTokens`，每组分别记录 A1/A2/B1/B2、模型版本与间隔，并保留缺失 cache 字段为未知。[官方缓存说明](https://ai.google.dev/gemini-api/docs/generate-content/caching)给的是提高命中机会的建议，不保证隐式缓存节省；[UsageMetadata](https://ai.google.dev/api/generate-content#UsageMetadata)定义的是缓存部分 token 数。本次没有直连 Gemini 复现，因此本报告的 DeepSeek 收益不构成 Gemini 收益证明。

本轮全部请求的未缓存输入下降约 27.9%，主回复请求增加 9 次。新增往返来自历史补查、防止重复写入、按 Run 重新加载工具和显式读取 Skill；不是零成本优化。主回复总命中率还受工具续接数量变化影响，因此同时报告首步。缓存可能跨请求共享，两个“每群首个回复”不能直接当作供应商绝对冷启动。顺序运行、随机回答和后续历史差异也限制了因果结论，不据此承诺长期 95%。

两版各有 2 次后台记忆 HTTP 400，均在兼容降级重试后成功；没有主回复失败、取消或未完成事件。145 / 154 次成功请求全部提供原始 cache 字段，并与 Runtime 适配后 usage 一致；失败请求单列。两版各 43 个后台任务均完成。最终候选没有协议修复。

最终候选的 15 组预期工具覆盖均完成。基线缺 `read_skill` 的一组是旧常驻正文模式造成的机械缺项：当时完整 Skill 已自动注入，不能称为没有执行技能。候选仅在当前点名的第 38 轮读取一次全文；后续第 41 轮没有历史点名提示，也没有多余的技能读取。笔记同 ID 从 v1 更新到 v2；饮食偏好改用画像写入成功，所以候选有 1 条 notebook 而基线有 2 条，不代表丢失该偏好。`memory` 查询实际返回非空结果。

27 条回复均有 Runtime delivery 记录；模拟对端最终收到 31 条普通消息和 2 张单节点转发卡。普通消息的 @/引用正确变成 OneBot segment，没有裸 `[up]` / `[diana-*]` 协议泄漏。转发卡正文通过 Runtime/events 复核，模拟端没有手机渲染验证，不能称为真实 QQ 接收验收。

## 原始实现的验证范围

新增回归通过真实 provider 适配器覆盖 Responses、Chat Completions、Anthropic、Gemini 的普通/流式请求：完整当前内容真正进入 HTTP、无法容纳时零 HTTP、并行工具批次整体保留或丢弃。Runner 另测 JSON 工具观察和强制收尾，不依赖 QQ 路径的 Current 标记。

还覆盖 Skill 长正文经真实 Runner 两次续读、JSON/Unicode 边界、旧 Skill 常驻设置不复活、每个 Run 独立加载、完整契约、最新调研状态和动态尾部不累计。前端在演示模式目视验证了 Skill 只读目录与搜索选项。

- `TZ=UTC go test -race -timeout=20m -json ./... -count=1`：26 个有测试的包全部通过，7,980 个测试/子测试通过，无 race、失败或超时，耗时 792.43 秒。另 6 个包没有测试。
- 完整快照有 170 个 skip 事件，其中 FFmpeg 缺失影响 41 个顶层媒体测试。随后安装 FFmpeg 7.1.5，校正其中一处旧提示文案断言；这 41 项及其子测试共 67 项在 `Asia/Taipei` 和 `UTC` 下分别全部通过（38.219 / 34.082 秒），没有继续跳过。
- 默认时区完整 race 的较早测试快照有一项旧工具白名单断言失败；最终修正后的 10 项助手合同回归通过（7.260 秒），最终 Agent 全包 race 通过（40.736 秒）；最终 UTC 全包也已包含该白名单修正。
- 其余跳过项包括需要显式开启的付费模型/真实 GitHub/浏览器集成、作者私有 trace 数据以及不适用的 macOS 平台测试。Xvfb 基础测试实际通过；WSLg 只读 X11 目录通过私有 mount namespace 隔离解决，没有改变全局挂载或跳过该测试。
- 前端 271 项测试、TypeScript 检查、生产构建通过；演示构建和浏览器目视检查完成，临时预览服务已停止。
- `gofmt -l .`、`git diff --check`、Python 编译、回放导出脱敏的离线检查通过。脱敏保留普通 `task-...` 标识，避免破坏 trace；原始记录、usage 与聚合结果已重新核对。

原始 trace、数据库、管理凭据和 API Key 保留在本机忽略目录，不随 PR 上传。回放方法见 [README](README.md)，集合见 [context-simplification.zh.json](../../docs/testing/context-simplification.zh.json)。这些是接近真实 Runtime 的合成测试，未覆盖真实 QQ 投递、真实图片/音视频、网络故障注入和整机重启；小样本与共享供应商缓存也不足以证明长期命中率或固定 95% 指标。
