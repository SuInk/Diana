# MaiBot reply composition — Go port

Upstream: https://github.com/Mai-with-u/MaiBot

Revision: `f9ec3670a3638d6a4708ee5253f7ffe2838c9415`

Original work: MaiBot contributors. Source files:

- `src/chat/replyer/maisaka_generator_base.py`
- `prompts/zh-CN/maisaka_replyer.prompt`
- `src/config/official_configs.py` (default reply style)
- `prompts/zh-CN/maisaka_chat.prompt` (embedded verbatim as `planner.prompt`)
- `src/maisaka/chat_loop_service.py` (planner template rendering and final reminder)
- `src/maisaka/builtin_tool/reply.py` (`reply_tool.json`, generated by executing the pinned schema builder with expression intent on and optional emoji/at/extensions off)
- `src/chat/replyer/maisaka_expression_selector.py` (`expressions.go`)

The Go files and embedded assets in this directory translate the upstream text composition methods and prompts into
Go. It retains the upstream GPL version 3 license, reproduced in `LICENSE`.

Changes: explicit Go input structures and supplied clock; no model, SQL, image,
plugin or global configuration dependencies; caller-provided instructions allow
Diana's delivery protocol. History conversion and selection of temporary style
remain caller responsibilities. Chinese whitespace normalization and the
300-Unicode-code-point target limit follow upstream behavior for ordinary chat.

Diana's production adapter now calls `Compose` for a separate reply-generation
stage. The host planner retains tools, permissions and full context and supplies
`reply_reference` and `reply_style` using the upstream reply-tool field contract
(`src/maisaka/builtin_tool/reply.py`). The model-facing planner now uses the
upstream template and reply tool, while the execution loop remains Diana's.
The previous custom JSON-planning prompt has been removed. The replyer receives visible chat/media and the selected reference,
not raw tool or memory blocks. It retains host identity/delivery requirements.
`Compose` is tested against the original Python bridge. Default group/private
attention text is copied from the pinned configuration; non-QQ hosts replace
the QQ-specific platform name with a generic group label.

The voice migration uses the upstream default reply style verbatim and the
upstream name/aliases/personality layout. MaiBot mode now uses the upstream
personality and behavior-style defaults as well. The host name and Soul remain
inputs. Explicit MaiBot settings, user-owned persona mode and group overrides
can replace those defaults; no remote configuration is rewritten by this port.
Empty identity falls back to neutral chat context rather than "is human".
Upstream experimental emotion is left at its neutral default. Diana's old
managed voice, emoji ban, mood, daypart, action and length/closing prompts are
not added in MaiBot mode. Temporary random styles remain disabled (upstream
default probability is zero).

Planner history represents sent chat as user data, following SessionBackedMessage;
replyer guided bot history is whitespace-normalized and limited to 500 Unicode
code points. The expression selector prompt, valid-ID selection (at most five)
and reference block are ported; the pool uses Diana's frequency store, which
does not have upstream situation/style pairs or vector retrieval. Malformed
selection JSON is ignored rather than repaired heuristically. Candidate IDs
must be JSON integers, excluding booleans.

Host adaptations: one admitted reply target per turn, tools_load discovery,
internal reply-to-finalize translation preserving execution guards, and existing
channel delivery. Upstream media-index attachments, wait/focus scheduling,
learning database, hooks and the full Maisaka reasoning engine are not included.
Do not describe this integration as a complete MaiBot server port.
